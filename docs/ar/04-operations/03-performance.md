# الأداء (performance)

أداء التعريب هو في معظمه أداء ما يفعله المزوّد. ويضيف المُعرِّب عملاً صغيراً حوله: فحوص وسائط،
ومشي ارتداد، ونداء منسّق، وتشخيصاً اختيارياً. هذا خبر جيد لتخطيط السعة، لأن اختيار المزوّد وشكل
الكتالوج، لا خط الأنابيب، هما ما يحدد كلفة البحث. وهو تحذير أيضاً: لا يستطيع منسّق سريع إنقاذ رحلة
قاعدة بيانات لكل طلب أو نداء ترجمة بعيد.

يفصل هذا الفصل الحقائق البنيوية (ما يفعله الكود، مؤكدة في المصدر) عن الإرشاد (ما يمكن تجربته). وهو
لا يحوّل أرقام القياس إلى وعد سعة. يحتوي المستودع اختبارات أداء بنمط الأدلة تسجّل قياسات، لكنها
تؤكد الصلاحية لا العتبات، لذا لأرقامها معنى فقط للجهاز والتشغيل الذين أنتجوها. وتُنشر لقطة واحدة
قابلة لإعادة الإنتاج في [دليل أداء](07-performance-evidence.md).

## المسار الساخن

ينفّذ نداء <code dir="ltr">LocalizeAsync</code>:

1. فحوص null وفحوص الإلغاء؛
2. اختيار المزوّد عبر <code dir="ltr">LocalizationProviderSelector</code>؛
3. استعلام مزوّد واحد لكل خطوة ارتداد، مع التوقف عند أول قالب؛
4. إبلاغ عن غياب إلى المصب الاختياري، أو نداء منسّق عند الإصابة؛
5. تشخيصاً محمياً بمستمع.

المزوّدون مطابقون تماماً، لذا فمشي الارتداد هو الحلقة الوحيدة. ولا تُستعلم الثقافة الثابتة أبداً،
وتُستعلم الثقافة الافتراضية مرة واحدة بعد مشي الآباء. لذلك يحدّ الغياب عمق الثقافة زائد واحد؛
وتحدّ الإصابة موضع أول تطابق. وفي الحالة الشائعة التي تملك فيها الثقافة المطلوبة المفتاح، يوجد
استعلام مزوّد واحد.

لا تُحوَّل الاستثناءات إلى غيابات. فإخفاقات قاعدة البيانات والكتالوجات المشوّهة والإلغاء وأخطاء
المنسّق تنتشر، فتصبح كلفة تبعية غير سليمة مرئية للمستدعي بدلاً من أن تصبح ارتداداً بصمت. راجع
[النموذج الذهني](../01-getting-started/04-mental-model.md).

## كلف المزوّدين

| المزوّد | البحث في الحالة المستقرة | كلفة أول استخدام | ملاحظات |
|---|---|---|---|
| Memory | بحث قاموس ترتيبي | ينسخ القاموس عند الإنشاء | بلا إدخال/إخراج؛ خريطة مسطحة واحدة تتجاهل الثقافة. |
| JSON / XML / PO (Portable Object) | بحث قاموس ترتيبي بعد التحميل | يحلّل الملف عند أول بحث | الجدول المحمَّل غير قابل للتغيير؛ والتحميل الفاشل لا يُخزَّن. |
| ResX / satellite | بحث مجموعة موارد عبر <code dir="ltr">ResourceManager</code> | تحميل مجموعة الموارد عند أول استخدام | ثقافة دقيقة، واستكشاف الآباء معطّل. |
| قاعدة بيانات (SQLite/SQL Server/MySQL/PostgreSQL) | فتح اتصال، تنفيذ قياسي، إغلاق | تدفئة مجمع الاتصالات | رحلة واحدة لكل خطوة ارتداد؛ بلا ذاكرة رسائل مدمجة. |
| مخزن EF Core | استعلام لكل نداء عبر مصنع سياق | تدفئة السياق وتجميع الاستعلام | كتابات الإدارة تضيف معاملة ويوميات وتدقيقاً وعمل إصدار. |
| Azure Translator | إصابة ذاكرة، وإلا HTTP | شبكة وJSON وملء ذاكرة | ذاكرة TTL (Time To Live)، ودمج الطلبات المتزامنة، وتجميع حتى 100 مفتاح، وتحميل مسبق، وتحديث. |
| Google Translate | HTTP لكل بحث | شبكة وJSON | بلا ذاكرة مزوّد أو تجميع أو تحميل مسبق أو تحديث. |

تحمّل مزوّدات الملفات كسولاً وتنشر الجدول المكتمل ذرّياً. بعد ذلك يكون البحث عملية قاموس ولا يمس
نظام الملفات. والمراقبة كلفة منفصلة: مراقب نظام ملفات ومؤقت تهدئة (debounce) لا يوجدان إلا عند
تفعيل <code dir="ltr">WatchForChanges</code>.

تفتح مزوّدات قواعد البيانات اتصالاً لكل بحث عبر مزوّد ADO.NET. وتجميع الاتصالات للمورّد، لا
للمكتبة؛ ولا تبقي المكتبة اتصالاً أو أمراً حياً بين النداءات. ولا توجد ذاكرة رسائل مدمجة. وإذا
نفّذت صفحة عشرين بحثاً في طلب وكان المزوّد قاعدة بيانات، فقد يكون ذلك عشرين رحلة قبل احتساب خطوات
الارتداد.

مخزن EF Core مسار مختلف. تمر القراءات عبر <code dir="ltr">IDbContextFactory</code> وسياق جديد
لكل نداء. والتعديلات المحكومة أغلى بحكم التصميم: تكتب صف الكتالوج، وتلحق صفوف يوميات إعادة
التشغيل، وتلحق سجلات تدقيق بسلسلة تجزئة، وتقدّم إصدار الكتالوج في معاملة واحدة. وقراءات التاريخ لا
تُخزَّن أبداً. خصص ميزانية للإدارة منفصلة عن عمليات بحث وقت التشغيل.

الترجمة مرتبطة بالشبكة. انتهاء ذاكرة Azure الافتراضي ساعة واحدة (<code dir="ltr">CachingEnabled</code>
صحيح افتراضياً)؛ والذاكرة لكل نسخة مزوّد، وتتشارك عمليات البحث المتزامنة للمفتاح/الثقافة نفسيهما
اكتساباً واحداً قيد التنفيذ. وتدفّئ <code dir="ltr">PreloadAsync</code> مفاتيح يوفّرها المستدعي،
وتُسقط <code dir="ltr">RefreshAsync</code> الذاكرة والحالة قيد التنفيذ. ولا يملك Google أياً من تلك
التسهيلات، فكل بحث نداء بعيد ما لم يضف المضيف ذاكرة خاصة به.

## طبقات التخزين المؤقت الموجودة

لا تفترض ذاكرة ليست في المصدر. الطبقات المدمجة هي:

- **لقطات مزوّد الملفات.** تحمّل JSON وXML وPO مرة واحدة وتخدم جدولاً غير قابل للتغيير. هذه لقطة،
  لا ذاكرة TTL؛ ويستبدلها <code dir="ltr">RefreshAsync</code> أو إعادة تحميل مراقَبة.
- **لقطة مزوّد الذاكرة.** يُنسخ القاموس عند الإنشاء ولا يُحدَّث أبداً.
- **ذاكرة ترجمة Azure.** ذاكرة TTL من BCL (Base Class Library) بدمج طلبات متزامنة، افتراضياً ساعة، ولا تُعطَّل إلا بـ
  <code dir="ltr">CachingEnabled = false</code>.
- **ذاكرة الترجمة والمسرد في Azure.** ذاكرة ترجمة مطابقة تماماً تختصر النداء الخارجي؛ ومسرد يفرض
  المصطلحات قبل الترجمة الآلية. وليس أي منهما ذاكرة عامة.
- **<code dir="ltr">CachedLocalizationStoreDecorator</code>.** يلف
  <code dir="ltr">ILocalizationStore</code> بـ <code dir="ltr">IMemoryCache</code>. ولإدخالات
  مجموعات الموارد مدة ثلاثين دقيقة؛ وتبطل إعادة تحميل ناجحة وتعديلات محكومة مطبَّقة الحالة
  المتأثرة.
- **<code dir="ltr">DistributedLocalizationStoreDecorator</code>.** يلف مخزناً بـ
  <code dir="ltr">IDistributedCache</code>، بانتهاء افتراضي ثلاثين دقيقة، ودمج طلبات متزامنة لكل
  عقدة، وإبطال بطابع جيل. وتتجاوز الأعضاء المتزامنة
  <code dir="ltr">TryGet*</code> الذاكرة الموزعة بحكم التصميم لأن التجريد غير متزامن فقط.

مزخرفات المخزن لا تُسجَّل بامتداد <code dir="ltr">Add...</code>؛ اربطها صراحةً. ومزخرفات الذاكرة
لكل عملية ما لم تستخدم الموزع. وانقطاع الذاكرة يتراجع إلى المخزن الداخلي، ولا يُبتلع الإلغاء أبداً.
ولا تملك مزوّدات رسائل قواعد البيانات وResX وsatellite وترجمة Google ذاكرة رسائل.

## ملاحظات التخصيص

هذه ملاحظات بنيوية من المصدر، لا أرقام تخصيص مقاسة:

- مسارا بحث الذاكرة والملف المحمَّل لا يخصصان مجموعة لكل بحث؛ إنهما ينادِيان
  <code dir="ltr">Dictionary.TryGetValue</code> ويعيدان السلسلة الموجودة.
- يبني <code dir="ltr">LocalizeWithContextAsync</code> سلسلة مركبة
  <code dir="ltr">context + '\u0004' + key</code> عندما يكون السياق غير فارغ. وذلك التخصيص لكل
  نداء.
- يشغّل <code dir="ltr">DefaultMessageFormatter</code> استبدال تعبير نمطي مجمّع ويخصص سلسلة النتيجة.
  ويمنح منسّقا ICU (International Components for Unicode) وMarkdown حالة محلل/منشئ لكل نداء؛ ولا يخزّن أي منهما القوالب المعروضة.
- التشخيص محمي بمستمع. وبلا <code dir="ltr">ActivityListener</code> وبلا أدوات مفعّلة، يتخطى خط
  الأنابيب إنشاء الأنشطة والقياسات. وعند وجود مستمعين، يدفع المراقب كلف التسجيل.
- مصب المفاتيح المفقودة اختياري. وبمصب null، يكون مسار الغياب فحص null. وبمصب، يمشي التقاط موضع
  النداء في المكدس.
- مسارا قاعدة البيانات والترجمة يخصصان أوامر وطلبات وكائنات استجابة لكل نداء؛ وتنتمي تلك الكلف إلى
  حد التبعية.

## إرشاد التوسع

**الذاكرة والملفات.** توسّع بنشر المحتوى نفسه على كل نسخة. وكل نسخة تحمّل لقطتها؛ ولا توجد ذاكرة
مشتركة بين النسخ لتنسيقها. ومراقبة الملفات لكل نسخة ويجب أن تكون معطّلة عادةً في الإنتاج، حيث
تكون الصورة أو الوحدة المركَّبة وحدة النشر.

**مزوّدات قواعد البيانات.** وسّع القراءات بتجميع الاتصالات، وفهرس فريد صحيح على
<code dir="ltr">(MessageKey, Culture)</code>، وسعة قاعدة بيانات تكفي استعلاماً قياسياً واحداً لكل
خطوة ارتداد. استخدم نسخة قراءة إذا كان تأخر النسخة مقبولاً؛ وإلا فاقرأ من الأساسي. وإذا كان حجم
الاستعلامات مرتفعاً جداً، أضف <code dir="ltr">CachedLocalizationStoreDecorator</code> لقراءات
المخزن فقط؛ فمزوّدات الرسائل لا تقبل مزخرفاً. ولعمليات بحث الرسائل، قلّل الرحلات بحل المفتاح مرة
واحدة لكل طلب أو بالتخزين المؤقت على مستوى التطبيق باستراتيجية إبطال متعمدة.

**مخزن EF Core.** تتشارك القراءات والكتابات قاعدة البيانات. ويسلسل المخزن التعديلات المحكومة لكل
نسخة ويعيد محاولة تحديث عدّاد الإصدار حتى خمس مرات قبل رمي
<code dir="ltr">DbUpdateConcurrencyException</code>؛ ولا تنسّق تلك البوابة داخل العملية كتاباً
خارج العملية. أضف قيوداً أو سلسل الكتابات خارجياً، وأبقِ حركة الإدارة بعيداً عن نسخ القراءة.
والمزخرف الموزع هو الطريقة المدمجة لمشاركة ذاكرة القراءة عبر العقد.

**مزوّدات الترجمة.** فضّل الترجمة دون اتصال أو بالدفعات لمحتوى الكتالوج. وفي وقت الطلب، ذاكرة Azure
ودمج الطلبات المتزامنة والتجميع ومحدد المعدل هي الضوابط المتاحة؛ ولا يقدّم Google أياً منها. عيّن
مهلة طلب وحد معدل مناسبين للاشتراك، وتوقع أن تكلف كل إصابة فائتة رحلة شبكة. ومزوّد الترجمة هو
المزوّد الوحيد، لذا لا يوجد كتالوج ملفات خلفه يمتص الإخفاقات.

**التنسيق.** المنسّق الافتراضي رخيص نسبةً إلى الإدخال/الإخراج لكنه ليس مجانياً. لعائلة قوالب ساخنة
جداً، خزّن النتيجة المنسّقة في موضع النداء بمفتاح ثقافة ووسائط. لا تضف ذاكرة داخل منسّق مشترك:
فليس لديه إشارة إبطال، والوسائط تتغير في كل نداء.

## قس قبل أن تحسّن

استخدم حلقة قياس تطابق مسار الإنتاج:

1. **عرّف السيناريو.** مزيج المفاتيح، وسلسلة الثقافة، ونسبة الإصابة/الغياب، والمزوّد، وحالة
   الذاكرة، والتزامن. فقياس إصابة دقيقة في الثقافة المطلوبة لا يتنبأ بصفحة تغيب في الثقافة
   الافتراضية عشرين مرة.
2. **افصل البارد عن الدافئ.** تحليل الملفات وتحميل مجموعات الموارد وتدفئة مجمع الاتصالات وملء
   ذاكرة الترجمة تنتمي إلى المسار البارد. قسها منفصلة عن الحالة المستقرة.
3. **قس التوزيع.** سجّل p50 وp95 وp99، لا المتوسط وحده. فعمر الارتداد وزمن قاعدة البيانات ثقيلا
   الذيل.
4. **عدّ العمل.** استعلامات المزوّد لكل بحث، وخطوات الارتداد، ورحلات قاعدة البيانات، وإصابات
   الذاكرة وغياباتها، وطلبات الترجمة، تفسّر تغير الزمن أفضل من زمن منقضٍ واحد.
5. **قس التخصيص.** استخدام
   <code dir="ltr">GC.GetAllocatedBytesForCurrentThread</code> حول كتل متكررة هو التقنية نفسها
   التي تستخدمها اختبارات أدلة المستودع. ومعدل التخصيص مهم تحت الحمل حتى عندما يبدو نداء واحد
   سريعاً.
6. **غيّر شيئاً واحداً.** أعد تشغيل السيناريو نفسه بعد تغيير واحد. لا تقارن تشغيلات على أجهزة أو
   إصدارات وقت تشغيل أو مجموعات بيانات مختلفة.

اختبارات أداء المستودع دليل غير بوابي، لا مجموعة قياس: تُوسم
<code dir="ltr">TestCategory=Performance</code>، وتعمل بلا توازٍ، وتطبع لقطة بيئة، وتؤكد فقط أن
القياسات موجبة ومنتهية. وتغطي بحث الذاكرة، والتحميل الأول والحالة المستقرة للملفات، وResX، وجسر
المخزن، وSQLite، وكلفة التشخيص. استخدمها كشكل مِحمل (harness) وكحوار انحدار، لا كوعد سعة. واللقطة
المقاسة وأوامر إعادة الإنتاج في [دليل أداء](07-performance-evidence.md).

إشارات وقت التشغيل المفيدة معرّفة بالفعل: <code dir="ltr">localization.lookup.duration</code> و
<code dir="ltr">localization.lookup.hits</code> و
<code dir="ltr">localization.lookup.misses</code> و
<code dir="ltr">localization.fallback.steps</code> وأدوات طلب/ذاكرة/مدة الترجمة تحت مقياس
<code dir="ltr">Jeninnet.Localization</code>. وتشمل وسوم النشاط المفتاح والثقافة، لكن نص القالب
لا يُوسم أبداً.

## مثال عملي: صفحة كتالوج بطيئة

صفحة تعرض شبكة منتجات بطيئة بالعربية فقط. المزوّد SQL Server. والثقافة الافتراضية
<code dir="ltr">en</code>، والكتالوج العربي ناقص.

يُظهر القياس عشرين بحثاً، كلٌّ يغيب في <code dir="ltr">ar</code> ثم يصيب
<code dir="ltr">en</code>: أربعون استعلاماً للمزوّد، لا عشرون. والإصلاح ليس منسّقاً أسرع؛ بل إكمال
الكتالوج العربي أو حل القيم مرة واحدة لكل طلب. وإذا كان مسموحاً عمداً أن يرتد الكتالوج، فاقبل
مضاعفة عدد الاستعلامات وخزّن بيانات الصفحة المحلولة على مستوى التطبيق باستراتيجية إبطال مرتبطة
بتغييرات الكتالوج. وإذا كانت البيانات يجب أن تكون حديثة، فأضف سعة قاعدة بيانات أو انقل الكتالوج
الساخن إلى مزوّد ملفات يطابق نموذج النشر.

## مآزق

**مأزق:** تحسين المنسّق عندما يكون المزوّد قاعدة بيانات. قس استعلامات المزوّد أولاً.

**مأزق:** التعامل مع أول بحث في مزوّد ملفات كحالة مستقرة. فالطلب الأول يدفع كلف التحليل؛ ودفّئه
إذا كانت البداية الباردة مهمة.

**مأزق:** افتراض أن مزوّدات قواعد البيانات تخزّن مؤقتاً. إنها لا تفعل؛ وكل خطوة ارتداد رحلة.

**مأزق:** تخزين القيم المفقودة إلى ما لا نهاية. فتعديل الكتالوج أو نشر جديد لن يبطل قاموساً على
مستوى المضيف ما لم تبنِ ذلك الإبطال.

**مأزق:** تفعيل مراقبة الملفات على محتوى غير قابل للتغيير. إنه يضيف مراقباً ومؤقتاً بلا فائدة.

**مأزق:** مقارنة تشغيلات القياس عبر أجهزة مختلفة. اختبارات المستودع تطبع لقطة بيئة لسبب.
