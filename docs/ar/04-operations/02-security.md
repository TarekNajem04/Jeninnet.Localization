# الأمان (security)

يجلس التعريب على حد ثقة يسهل تفويته. فبيانات اعتماد المترجمين وملفات الكتالوج ورفعات التبادل
ومخزن الإدارة كلها مدخلات إلى نظام إنتاجي، وبعضها يوفّره أشخاص أو خدمات خارج فريق النشر. يصف هذا
الفصل سطح التهديد كما ينفّذه الكود فعلاً، والضوابط التي تخص تطبيق المضيف لا المكتبة.

## حدود الثقة

أربعة مدخلات تستحق معالجة منفصلة:

1. **محتوى الكتالوج** — القوالب والمفاتيح وملاحظات المترجم. وكتالوجات الملفات عادةً آثار نشر
   موثوقة؛ أما كتالوج قاعدة بيانات أو واجهة إدارة فقد تقبل محتوى من غير المطوّرين.
2. **ملفات التبادل** — مستندات PO (Portable Object) وXLIFF وCSV وResX التي ينتجها المترجمون أو المورّدون. وهذه
   مدخلات غير موثوقة حتى عندما يكون المرسل موثوقاً.
3. **بيانات اعتماد المترجم ونقاط النهاية** — مفاتيح API وعناوين URL الأساسية لـ Azure
   Translator أو Google Translate.
4. **مخزن الإدارة** — مسار الكتابة المحكوم، وأثر تدقيقه، وحساب قاعدة البيانات الذي يسنده.

توفّر المكتبة التحليل والتحقق وفحوص القدرة. وهي لا تصادق المستخدمين ولا تفوّض نقاط النهاية ولا
تشفّر التخزين ولا تقرر هل مورّد الترجمة موثوق. تلك مسؤوليات مضيف، ويجب تصميمها صراحةً.

## بيانات اعتماد المترجم

تُرسل <code dir="ltr">AzureTranslationOptions.ApiKey</code> في ترويسة
<code dir="ltr">Ocp-Apim-Subscription-Key</code> عبر <code dir="ltr">HttpClient</code>؛ وتُرسل
المنطقة الاختيارية في <code dir="ltr">Ocp-Apim-Subscription-Region</code>. ويُرسل
<code dir="ltr">GoogleTranslationOptions.ApiKey</code> كوسيطة الاستعلام الموثّقة
<code dir="ltr">key</code> على نقطة نهاية v2. وهذا الفرق مهم تشغيلياً: فسلاسل الاستعلام أكثر
احتمالاً للظهور في سجلات الوسيط وسجلات وصول البوابة وتليمترية الأعطال. لا تفعّل تسجيل الطلبات
الذي يلتقط عناوين URL كاملة لمزوّد Google.

يتحقق الخياران من نقطة النهاية كـ URI مطلق بـ <code dir="ltr">http</code> أو
<code dir="ltr">https</code>. ولا يثبّت المزوّد مضيفاً، لذا فالتكوين جزء من حد الأمان. ثبّت نقطة
النهاية على الخدمة المتوقعة في الإنتاج، وارفض التجاوزات من مصادر تكوين غير موثوقة، واشترط HTTPS.
فالمهاجم القادر على إعادة كتابة التكوين يستطيع توجيه مفتاح API إلى مضيف يتحكم به.

تعامل مع المفاتيح كأسرار محددة النطاق بالبيئة:

- استخدم .NET User Secrets أثناء التطوير المحلي؛ ولا تلتزم المفاتيح في
  <code dir="ltr">appsettings.json</code> أبداً.
- استخدم مخزن أسرار المنصة أو متغيرات بيئة محمية في الإنتاج.
- أعطِ كل بيئة مفتاحها الخاص وبدّله وفق جدول.
- قيّد الوصول الشبكي الصادر إلى نقطة نهاية الترجمة.
- لا تسجّل كائن الخيارات ولا تُفرّغ التكوين عند بدء التشغيل.

ترسل مزوّدات الترجمة مفتاح البحث كنص مصدر. لا ترمّز بيانات شخصية أو رموز وصول أو أسراراً أخرى في
مفاتيح الرسائل أبداً: فالمفتاح يُنقل إلى الخدمة البعيدة وقد تحتفظ به. وإذا كان المحتوى حساساً،
فترجم الكتالوجات دون اتصال واخدم النتيجة من مزوّد ملفات أو قاعدة بيانات.

## ملفات التبادل غير الموثوقة

تتبع حزم التبادل الأربع نموذج تحقق ثم تطبيق: يُحلَّل المستند كله ويُتحقق منه قبل حساب أي شيء،
ويعيد الاستيراد على مستوى الملف كتابة الكتالوج الهدف مرة واحدة على الأكثر. والتشغيل التجريبي لا
يغيّر شيئاً. وهذا يحمي الهدف من الكتابات الجزئية، لكنه لا يجعل مستنداً غير موثوق آمناً للمعالجة
دون حدود موارد.

### الصيغ القائمة على XML

يستخدم مزوّد XML الدالة <code dir="ltr">XDocument.Load</code>، ويستخدم مرمّزا XLIFF (XML Localization Interchange File Format) وResX الدالة
<code dir="ltr">XDocument.Parse</code>، دون إعدادات مخصصة
([مزوّد XML](https://github.com/TarekNajem04/Jeninnet.Localization/blob/main/src/providers/Jeninnet.Localization.Providers.Xml/XmlMessageProvider.cs)،
[محلل XLIFF](https://github.com/TarekNajem04/Jeninnet.Localization/blob/main/src/interchange/Jeninnet.Localization.Interchange.Xliff/XliffDocumentParser.cs)،
[مرمّز ResX](https://github.com/TarekNajem04/Jeninnet.Localization/blob/main/src/interchange/Jeninnet.Localization.Interchange.ResX/ResXTextCodec.cs)).
ولا يُقدَّم <code dir="ltr">XmlResolver</code>، لذا لا يُفعَّل حل الكيانات الخارجية: فالكيان
الخارجي المعلن لا يقرأ ملفاً أو URL. وهذا يحجب كشف XXE الكلاسيكي، لكن DTD لا يُرفض: يحلّل LINQ to
XML تصريحات DTD الداخلية ويوسّع الكيانات الداخلية ضمن حد توسّع الكيانات في وقت التشغيل. وإذا كانت
سياسيتك تحظر DTD، فارفض المستندات التي تحوي <code dir="ltr">&lt;!DOCTYPE&gt;</code> قبل التحليل
أو استخدم قارئاً مكوَّناً بـ <code dir="ltr">DtdProcessing.Prohibit</code>؛ فواجهات مستوى الملف لا
تكشف إعدادات القارئ.

لا يوجد حد صريح للحجم أو عدد المحارف أو العمق. فالمستند الكبير السليم الشكل يُقرأ في الذاكرة،
وتوسّع الكيانات الداخلية قد يستهلك CPU قبل بلوغ حد وقت التشغيل. افرض حداً بالبايت قبل نداء
المحلل، وارفض DTD غير المتوقع، وشغّل الاستيراد بميزانية وقت داخل عامل قابل للإنهاء.

### ResX بلا تفعيل أنواع

مرمّز تبادل ResX مكتوب يدوياً ويقرأ فقط إدخالات <code dir="ltr">data</code> التي تحمل
<code dir="ltr">name</code> و<code dir="ltr">value</code> و<code dir="ltr">comment</code>. ويتجاهل
عنصري الجذر <code dir="ltr">assembly</code>/<code dir="ltr">metadata</code> ويعلّم الإدخالات
ذات النوع <code dir="ltr">UnsupportedKey</code> بدلاً من إنشائها. وهذا يتجنب سطح تفعيل الأنواع في
قارئ موارد عام. أبقِه كذلك: لا تمرّر ResX غير موثوق عبر قارئ مختلف يفكّ تسلسل أنواع عشوائية.

### JSON وCSV وPO

يقرأ مرمّز كتالوج JSON الملف كله بـ <code dir="ltr">File.ReadAllBytes</code> ويحلله بـ
<code dir="ltr">JsonDocument</code>؛ والعمق الأقصى الافتراضي 64. وقارئا CSV وPO مكتوبان يدوياً
ويقرآن المستند كله كنص أيضاً. ويتحقق تحليل PO وMO من البنية والحدود: يفحص قارئ MO (Machine Object) إزاحات الجدول
وأطوال السلاسل، ويفكّ UTF-8 (Unicode Transformation Format, 8-bit) الصارم مع رفض البايتات غير الصالحة لا استبدالها
([محلل MO](https://github.com/TarekNajem04/Jeninnet.Localization/blob/main/src/providers/Jeninnet.Localization.Providers.Po/MoParser.cs)).

هذه إجراءات صحة وسلامة ذاكرة، لا حدود حجم. فملف CSV أو PO بحجم عدة غيغابايتات سيظل يستهلك ذاكرة
متناسبة مع حجمه. افرض حجم الرفع وعدد الصفوف ووقت المعالجة عند حد الاستيعاب.

### الأرشيفات والمسارات

لا تفكّ المكتبة ZIP أو غيره من الأرشيفات. لذا فـ"قنبلة zip" ليست ميزة محلل؛ إنها خطر في أي سير
عمل يقبل حزمة مضغوطة من ملفات XLIFF أو PO. وإذا كان الاستيعاب يقبل أرشيفات، فطبّق حدود فك الضغط
(عدد الإدخالات، والبايتات غير المضغوطة، ونسبة الضغط) قبل الاستخراج، ولا تثق أبداً باسم إدخال
كمسار نظام ملفات.

تأخذ واجهات التبادل على مستوى الملف مسارات يوفّرها المستدعي وتقرأ أو تكتب تلك المسارات بالضبط. وهي
لا تستنتج مساراً من اسم ملف مرفوع. وإذا قبلت نقطة نهاية HTTP رفعاً، فعلى المضيف توليد اسم مؤقت
آمن، وإبقاء الملف داخل دليل مخصص، وعدم تمرير مسار يتحكم به المستخدم مباشرةً إلى
<code dir="ltr">ImportCatalogFiles</code> أو <code dir="ltr">ExportCatalogFiles</code>.

### تطبيق محتوى غير موثوق

استخدم <code dir="ltr">DryRun</code> أولاً وافحص التقرير. فالتبادل لا يختلق مفاتيح: تُبلَّغ
المفاتيح المجهولة كـ <code dir="ltr">UnknownKey</code>، والإدخالات غير المدعومة كـ
<code dir="ltr">UnsupportedKey</code>، والمصادر القديمة كـ
<code dir="ltr">StaleSource</code> حيث تستطيع الصيغة تمثيلها. طبّق فقط بعد التحقق، وطبّق عبر مسار
المخزن المحكوم عندما يكون الهدف مجموعة موارد. واستيرادات ملفات ResX وCSV وPO تكتب ملفات كتالوج؛
ولا تصادق المترجم ولا تعتمد المحتوى.

## تفويض إدارة المخزن

لا تملك المكتبة طبقة مصادقة أو تفويض. فـ <code dir="ltr">IResourceAdminStore</code> عقد قدرة:
يقول <code dir="ltr">SupportsAdministration</code> هل يستطيع المخزن التعديل، ويرمي
<code dir="ltr">RequireAdmin()</code> الاستثناء
<code dir="ltr">StoreReadOnlyException</code> عندما لا يستطيع. وليس ذلك قرار تحكم في الوصول. وعلى
المضيف تفويض المستدعي قبل نداء أي دالة إدارة.

قواعد عملية:

- لا تكشف مخزن الإدارة عبر نقطة نهاية عامة. ضعه خلف مصادقة التطبيق وفحوص الأدوار وحمايات CSRF.
- تعامل مع قيمة <code dir="ltr">Actor</code> في
  <code dir="ltr">ResourceAdminOptions</code> كوسم تدقيق، لا كدليل هوية. املأها من الأصل
  المصادَق، لا من جسم طلب أبداً.
- استخدم حساب قاعدة بيانات للقراءة فقط لعمليات بحث الرسائل، وحساباً منفصلاً قادراً على الكتابة
  لعملية الإدارة فقط.
- أبقِ سطح الإدارة على قاعدة البيانات الأساسية؛ لا توجّهه إلى نسخة قراءة.
- سجّل قرارات التفويض وتعديلات الإدارة، لكن لا تسجّل قيم القوالب من حدث التدقيق أبداً ما لم يكن
  مخزن السجلات معتمداً لمحتوى الكتالوج.

تُعالج حقن SQL عند حد المزوّد. فاستعلامات رسائل قواعد البيانات تمرّر
<code dir="ltr">MessageKey</code> و<code dir="ltr">Culture</code> كوسائط؛ وتُهرَّب المعرّفات حسب
المورّد ويُتحقق من اسم الجدول عبر
<code dir="ltr">DatabaseLocalizationOptions.TableName</code>
([الصنف الأساس لمزوّدات قواعد البيانات](https://github.com/TarekNajem04/Jeninnet.Localization/blob/main/src/providers/Jeninnet.Localization.Providers.Database.Abstractions/DatabaseMessageProviderBase.cs)).
ولا يحمي ذلك تنفيذ مخزن مخصصاً أو نقطة نهاية إدارة مكتوبة يدوياً.

## سلامة التدقيق وسريته

أثر التدقيق المحفوظ سلسلة تجزئة: يحمل كل <code dir="ltr">LocalizationAuditRecord</code> الخاصيتين
<code dir="ltr">PreviousHash</code> و<code dir="ltr">ChainHash</code>، ويعيد
<code dir="ltr">VerifyHistoryAsync</code> حساب السلسلة. وأي تعديل أو إدراج أو إزالة يكسرها ما لم
تُعَد كتابة كل سجل لاحق. والسلسلة **غير مرساة**: فالمهاجم القادر على إعادة كتابة الأثر كله يستطيع
إعادة حساب كل تجزئة. تعامل مع التحقق كدليل عبث في ظل ضوابط تشغيلية عادية، لا كدليل ضد مسؤول قاعدة
بيانات متميز. وإذا تطلب نموذج التهديد دليلاً أقوى، فصدّر رؤوس السلسلة أو نتائج التحقق الدورية إلى
مخزن خارجي للإضافة فقط.

لا يُحفظ نص القالب في سجلات التدقيق. و<code dir="ltr">OldValueHash</code> و
<code dir="ltr">NewValueHash</code> تجزئتا SHA-256 (Secure Hash Algorithm, 256-bit) بالنظام السادس عشري الصغير لبايتات القالب بترميز
UTF-8، غير مملّحتين عمداً كي تعمل المساواة وكشف التغيير عبر السجلات. والتجزئات غير المملّحة لسلاسل
قصيرة متوقعة يمكن تخمينها دون اتصال؛ وهي ليست آلية سرية.

يوميات إعادة التشغيل مختلفة. يحفظ <code dir="ltr">StringVersions</code> قيم القالب الفعلية لأن
القراءات عند إصدار يجب أن تعيد إنتاج الكتالوج. احمِ ذلك الجدول بفئة السرية نفسها التي تحمي بها
جدول <code dir="ltr">LocalizedStrings</code> الحي، بما في ذلك النسخ الاحتياطية والوصول للقراءة.
أثر التدقيق منقّح؛ ويوميات الإصدارات ليست كذلك.

حدث <code dir="ltr">Audited</code> الحي متزامن وداخل العملية. والمعالج الذي يرمي ينشر استثناءً بعد
أن يكون التعديل قد التزم بالفعل. أبقِ المعالجات سريعة وغير رامية وخالية من الأسرار؛ واحفظ
المساءلة عبر <code dir="ltr">IResourceHistoryStore</code>، لا عبر سطر سجل.

## أقل امتياز لحسابات قاعدة البيانات

افصل الأدوار التي تقرأ الرسائل عن الأدوار التي تديرها.

| الدور | الوصول المطلوب |
|---|---|
| مزوّد الرسائل | <code dir="ltr">SELECT</code> على <code dir="ltr">LocalizationMessages</code> (أو الجدول المكوَّن). بلا كتابات وبلا DDL. |
| قارئ مخزن EF | <code dir="ltr">SELECT</code> على <code dir="ltr">LocalizedStrings</code> وجداول القراءة المساندة التي يستخدمها التطبيق. |
| مسؤول محكوم | <code dir="ltr">SELECT</code> و<code dir="ltr">INSERT</code> و<code dir="ltr">UPDATE</code> و<code dir="ltr">DELETE</code> على جداول المخزن، إضافة إلى عدّاد الإصدار وجداول التدقيق/اليوميات. |
| هوية الترحيل | حقوق DDL تُستخدم أثناء النشر فقط، لا بواسطة التطبيق العامل. |

امنح حقوق المخطط بضيق، وتجنّب <code dir="ltr">db_owner</code> لحساب وقت التشغيل، واشترط TLS على
الاتصال، وأبقِ سلاسل الاتصال في مخزن الأسرار. وإذا دعمت قاعدة البيانات أمان مستوى الصف أو مخططات
منفصلة لكل مستأجر، فاستخدمها؛ فالمكتبة لا تقسم المستأجرين عنك. والنسخ الاحتياطية ترث سرية الكتالوج
واليوميات، لذا شفّرها وقيّد الوصول إلى الاستعادة.

## التبعيات والاستجابة للثغرات

تدقيق الاستعادة مفعّل في كل مشروع: <code dir="ltr">NuGetAudit</code> مفعّل، و<code dir="ltr">NuGetAuditMode</code>
هو <code dir="ltr">all</code> (الحزم المباشرة والتابعة)، والمستوى <code dir="ltr">low</code>. وتُعامل
التحذيرات <code dir="ltr">NU1901</code>–<code dir="ltr">NU1904</code> كأخطاء، فالتبعية المصابة توقف
الاستعادة وCI بدلاً من إنتاج تحذير يمكن تجاهله.

يغطي Dependabot ومراجعة المشرفين تحديثات الحزم. عملية الاستجابة:

1. تأكيد تقرير ثغرة خاص خلال يومي عمل.
2. فرز الحزمة والإصدار وأهداف التشغيل المتأثرة؛ ونشر إصدار معالج أو حل موثّق للثغرات الحرجة/العالية
   خلال سبعة أيام.
3. إصلاح الثغرات المتوسطة خلال 30 يوماً؛ وتُعالج المنخفضة في التحديث المجدول التالي.
4. إعادة تشغيل الاستعادة والتحقق من الحزم والمستهلك ومصفوفة الاختبارات كاملة قبل نشر الإصلاح.
5. توثيق أي استثناء مؤقت بمعرّف التقرير والحزم المتأثرة والضابط التعويضي وتاريخ الانتهاء. لا تُكتم
   الثغرة دون تاريخ انتهاء.

أبلغ عن الثغرات المحتملة خصوصاً عبر GitHub Security Advisories، لا عبر مشكلة عامة. وتبقى روابط
المستودع والإبلاغ الأساسية في README وسياسة
[SECURITY.md](https://github.com/TarekNajem04/Jeninnet.Localization/blob/main/.github/SECURITY.md).
## قائمة توصيات

- [ ] تُحفظ مفاتيح الترجمة في مخزن أسرار، محددة النطاق لكل بيئة، وتُبدَّل.
- [ ] تُثبَّت نقاط نهاية الترجمة على المضيف المتوقع ويُشترط HTTPS.
- [ ] لا تحوي مفاتيح الرسائل بيانات شخصية أو أسراراً ترسل إلى خدمة ترجمة.
- [ ] يفرض استيعاب التبادل حدود حجم الملف وعدد الصفوف ووقت المعالجة.
- [ ] يفرض استيعاب الأرشيف (إن وجد) حدود عدد الإدخالات والحجم غير المضغوط ونسبة الضغط.
- [ ] تُكتب الملفات المرفوعة في مسار مولّد داخل دليل مخصص.
- [ ] يشغّل استيراد التبادل <code dir="ltr">DryRun</code> أولاً ويطبّق المحتوى المتحقق منه فقط.
- [ ] تتطلب نقاط نهاية الإدارة مصادقة وتفويضاً؛ وتأتي <code dir="ltr">Actor</code> من الأصل
  المصادَق.
- [ ] حسابات قاعدة البيانات وقت التشغيل للقراءة فقط؛ وحقوق الترحيل منفصلة.
- [ ] تُتحقق سلسلة التدقيق وفق جدول ويُحتفظ بدليل التحقق خارجياً.
- [ ] يُقيَّد الوصول إلى <code dir="ltr">StringVersions</code> و
  <code dir="ltr">LocalizedStrings</code> والنسخ الاحتياطية كبيانات كتالوج.
- [ ] لا تحوي السجلات قوالب أو مفاتيح ببيانات شخصية مضمّنة أو مفاتيح API.

## مآزق

**مأزق:** التعامل مع <code dir="ltr">SupportsAdministration</code> كتفويض. إنها تقول فقط إن
المخزن يستطيع التعديل.

**مأزق:** وضع مفتاح Google API في URL وتفعيل تسجيل الطلبات كامل URL. فسلاسل الاستعلام تُلتقط
عادةً.

**مأزق:** قبول ملف XLIFF من مورّد بلا حد حجم لأن "المحلل يتحقق من المخطط". فالتحقق ليس تحكماً في
الموارد.

**مأزق:** افتراض أن سلسلة التجزئة تثبت الأصالة ضد مسؤول قاعدة بيانات. إنها دليل عبث غير مرساة.
