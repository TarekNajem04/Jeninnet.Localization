# الترجمة الآلية (machine translation)

مزوّد الترجمة مزوّد رسائل عادي بنموذج كلفة غير عادي. المفتاح الذي تمرّره هو النص المصدر، والثقافة
المطلوبة هي اللغة الهدف، والقيمة تأتي من خدمة عن بُعد. وكل غياب من الذاكرة المؤقتة نداء شبكي قد
يكلّف مالاً أو يفشل أو يعيد شيئاً يجب أن يراجعه إنسان.

هذا يجعل الترجمة الآلية قرار منتج، لا بديلاً مباشراً لكتالوج. يغطي هذا الفصل المزوّدين، ونموذج
المرونة والتجميع في Azure، وسير عمل المراجعة الذي يمنع مخرجات الآلة من أن تصبح نصاً إنتاجياً بلا
مراجعة.

## ما يفعله المزوّدان فعلاً

تستهدف <code dir="ltr">Jeninnet.Localization.Translation.Azure</code> واجهة Azure Translator v3
REST. وتستهدف <code dir="ltr">Jeninnet.Localization.Translation.Google</code> الطريقة
<code dir="ltr">translate</code> الموروثة في Google Cloud Translation v2 REST. وكلاهما يعامل
مفتاح الرسالة كنص مصدر ويترجمه إلى الثقافة المطلوبة. ويعيد بحث الثقافة الثابتة
<code dir="ltr">null</code> فوراً دون طلب HTTP.

<div dir="ltr">

```csharp
services.AddAzureTranslationLocalization(options => {
    options.ApiKey = configuration["AzureTranslator:ApiKey"]!;
    options.Region = configuration["AzureTranslator:Region"];
    options.CachingEnabled = true;
});
```

</div>

<div dir="ltr">

```csharp
services.AddGoogleTranslationLocalization(options => {
    options.ApiKey = configuration["GoogleTranslate:ApiKey"]!;
});
```

</div>

يتحقق التسجيلان فوراً عند استخدام تحميل المفوّض: فـ <code dir="ltr">ApiKey</code> الفارغ أو
<code dir="ltr">Endpoint</code> غير الصالح يفشل عند التسجيل. وتقرأ التحميلات بلا وسائط عبر
<code dir="ltr">IOptions&lt;T&gt;</code> وترمي
<code dir="ltr">InvalidOperationException</code> عندما يُنشأ المزوّد بخيارات غير صالحة.

**مأزق:** تسجيل مزوّد ترجمة إلى جانب مزوّد ملفات أو قاعدة بيانات. ترمي قاعدة المزوّد الواحد بالضبط
عند الحل. لا يمكن وضع مزوّد ترجمة خلف كتالوج، ولا استخدام كتالوج كبديل خلفه. راجع
[النموذج الذهني](../01-getting-started/04-mental-model.md).

## قدرات Azure

Azure هو المزوّد القادر. ينفّذ عقود القدرات الاختيارية ويبلّغ عنها بصدق لكل نسخة:

- **البحث المجمّع** — ترسل <code dir="ltr">GetMessageTemplatesAsync</code> حتى 100 مفتاح في
  الطلب الواحد.
- **التخزين المؤقت** — ذاكرة مؤقتة محدودة بمدة صلاحية (TTL (Time To Live)) بسعة 4096 إدخالاً، مفتاحية بـ
  <code dir="ltr">(key, culture)</code>، وافتراضياً ساعة واحدة. وتكون
  <code dir="ltr">Supports(Caching)</code> خاطئة عندما يكون
  <code dir="ltr">CachingEnabled</code> خاطئاً.
- **دمج الطلبات المتزامنة (single-flight)** — تتشارك عمليات البحث المتزامنة للمفتاح والثقافة
  نفسيهما اكتساباً واحداً. وتنضم نداءات التجميع إلى المفاتيح قيد التنفيذ بدلاً من بدء طلب ثانٍ.
- **التحميل المسبق** — تدفّئ <code dir="ltr">PreloadAsync</code> الذاكرة المؤقتة لمفاتيح يوفّرها
  المستدعي عندما يكون التخزين المؤقت مفعّلاً.
- **التحديث** — تمسح <code dir="ltr">RefreshAsync</code> الذاكرة المؤقتة وتقدّم جيلاً كي لا
  يعيد اكتمال قبل التحديث ملء حالة أُبطلت. ولا تُلغى الطلبات قيد التنفيذ.
- **الأحداث** — يبلّغ <code dir="ltr">TranslationAcquired</code> و
  <code dir="ltr">AcquisitionFailed</code> عن نتائج الاكتساب الخارجي.
- **ذاكرة الترجمة** — تُستشار <code dir="ltr">ITranslationMemory</code> قبل أي نداء مدفوع.
  والإصابة تنفّذ صفر نداءات API ولا ترفع حدث اكتساب.
- **المسرد** — يفرض <code dir="ltr">MessageGlossary</code> ترجمات مصطلحات لكل ثقافة باستبدال
  المصطلحات المطابقة برموز نائبة قبل الطلب واستعادة الأهداف المفروضة بعده.

ترتيب الحل عند غياب من الذاكرة المؤقتة هو: ذاكرة الترجمة، ثم الترجمة الآلية المحمية بالمسرد، ثم
كتابة النتيجة في ذاكرة TTL. ويُلتقط المسرد في لقطة عند إنشاء المزوّد؛ ولا يغيّر تسجيل لاحق على
<code dir="ltr">MessageGlossary</code> نفسها مزوّداً قائماً. ويُلتقط مرجع مخزن ذاكرة الترجمة عند
الإنشاء، وقد يتغير محتواه؛ حدّث المزوّد لإسقاط النتائج المخزّنة التي تحجب إدخالات محدَّثة.

لا تُكتب الترجمات الآلية في ذاكرة الترجمة أبداً. فالذاكرة تحمل الترجمات المعتمدة فقط. وهذا هو
الحد بين مسودة ونتيجة مُراجَعة.

## مرونة Azure

تمر كل عملية تبادل مقطع عبر خط أنابيب يملكه المزوّد، من الخارج إلى الداخل:
<code dir="ltr">Timeout → Retry → Breaker → RateLimit → HTTP</code>. والسياسات آلات حالة من BCL (Base Class Library)
فقط، وكل توقيت يستخدم ساعة قابلة للحقن كي تكون الاختبارات حتمية.

| الخيار | الافتراضي | السلوك |
|---|---|---|
| <code dir="ltr">RequestTimeout</code> | 30 ثانية | ميزانية كل مقطع شاملة المحاولات والتراجع وانتظارات محدد المعدل. ويظهر الانتهاء كـ <code dir="ltr">OperationCanceledException</code>. |
| <code dir="ltr">RetryMaxAttempts</code> | 3 | محاولات HTTP لكل مقطع، بما فيها الأولى. لا تُعاد إلا إخفاقات الشبكة والمهل وHTTP 408/429/5xx. |
| <code dir="ltr">RetryBaseDelay</code> | 200 ms | أساس التراجع الأسي (<code dir="ltr">base × 2^(n-1)</code>)، محدوداً بـ <code dir="ltr">RetryMaxDelay</code>، مع تشتيت حتى 25%. |
| <code dir="ltr">RetryMaxDelay</code> | 5 ثوانٍ | سقف تأخير تراجع واحد قبل التشتيت. |
| <code dir="ltr">BreakerFailureThreshold</code> | 5 | إخفاقات محاولات عابرة متتالية تفتح القاطع. |
| <code dir="ltr">BreakerOpenDuration</code> | 30 ثانية | مدة الفتح قبل فحص نصف مفتوح واحد. والنجاح يغلق؛ والفشل يعيد الفتح. |
| <code dir="ltr">RateLimitRequestsPerSecond</code> | 0 (معطّل) | معدل إعادة تعبئة دلو الرموز من جهة العميل. والقيم الموجبة تنظّم كل محاولة HTTP. |
| <code dir="ltr">RateLimitBurstSize</code> | 1 | سعة الدفعة الفورية عند تفعيل تحديد المعدل. |

المهلة نهائية ولا تُعاد أبداً. وإلغاء المستدعي الحقيقي لا يُعاد ولا يسجّله القاطع ولا يرفع أي حدث
اكتساب. وأثناء فتح القاطع، تفشل عمليات الاكتساب سريعاً بـ
<code dir="ltr">BrokenCircuitException</code> ولا يُنفّذ طلب HTTP.

حالة المرونة لكل نسخة مزوّد: قاطع واحد ودلو رموز واحد يتشاركهما كل المفاتيح والثقافات ومسارات
البحث. وهذا مقصود. فالاشتراك المحدود المعدل يجب أن يبطئ المزوّد كله، لا مفتاحاً واحداً.

## إدارة الدفعات

تعيد <code dir="ltr">TranslationBatchJob</code> تعبئة الكتالوجات عبر خط أنابيب المزوّد بدلاً من
تجاوزه. تأخذ النوع المحدد <code dir="ltr">AzureTranslationProvider</code>، وتترجم المفاتيح
المتمايزة عبر الثقافات تسلسلياً، وتبلّغ عن التقدم كل نافذة من 100 مفتاح. ويعرض تسجيل DI (Dependency Injection) المزوّد
كـ <code dir="ltr">IInnerMessageProvider</code>؛ حوّل النسخة المحلولة الواحدة، أو سجّل النوع
المحدد أو أنشئه بنفسك.

<div dir="ltr">

```csharp
var job = new TranslationBatchJob(azureProvider);

var estimate = await job.EstimateAsync(keys, cultures, cancellationToken);
// estimate.TotalKeys, FreeKeys, BillableKeys, BillableCalls

var result = await job.RunAsync(keys, cultures, progress, cancellationToken);
// result.TranslatedCount, CachedCount, FailedCount, Entries
```

</div>

<code dir="ltr">EstimateAsync</code> تشغيل تجريبي بلا آثار جانبية. تحاكي نوافذ المقاطع للتشغيل
الحقيقي مقابل الطبقات المحلية للمزوّد: إصابات الذاكرة المؤقتة وذاكرة الترجمة تُحتسب مجانية. ويفترض
عدّاد النداءات المدفوعة مزوّداً ساكناً ونقلاً بلا أخطاء؛ أما إعادة المحاولة والكتّاب المتزامنون
وانتهاء الذاكرة المؤقتة فتغيّر الرقم الحقيقي. وإعادة تشغيل فورية لتعبئة مكتملة تقدّر صفر نداءات
ما دامت الذاكرة دافئة.

ينتج <code dir="ltr">RunAsync</code> إدخال سجل واحداً لكل مفتاح متمايز لكل ثقافة:

- <code dir="ltr">Translated</code> — نتيجة خدمة جديدة. وقالب <code dir="ltr">null</code> يعني
  أن الخدمة حلّت المفتاح كمفقود.
- <code dir="ltr">Cached</code> — خُدم من ذاكرة المزوّد المؤقتة أو من ذاكرة الترجمة.
- <code dir="ltr">Failed</code> — فشل اكتساب المقطع. ويُسجَّل السبب بالشكل
  <code dir="ltr">ExceptionType: message</code>.

إخفاقات المقاطع لا توقف الدفعة أبداً. تُترجم المفاتيح المكررة مرة واحدة، وتُرفض الثقافات الثابتة
مسبقاً، ومجموعة المفاتيح الفارغة بلا أثر. والإلغاء يرمي
<code dir="ltr">TranslationBatchCancelledException</code> (وهو
<code dir="ltr">OperationCanceledException</code>) حاملاً السجل الجزئي على
<code dir="ltr">PartialResult</code>، فلا يضيع العمل المكتمل. ولا تنفّذ المهمة أي كتابات؛ وتطبيق
السجل على مخزن أو كتالوج خطوة منفصلة مُراجَعة.

## سطح Google الأدنى

ينفّذ Google البحث الإلزامي أحادي المفتاح فقط. وتعيد
<code dir="ltr">Supports</code> القيمة false لكل ميزة: لا تجميع، ولا ذاكرة مؤقتة، ولا تحميل
مسبق، ولا تحديث، ولا أحداث اكتساب. ويمرّر البحث المرجعي رمز إلغاء المستدعي إلى
<code dir="ltr">SendAsync</code> و<code dir="ltr">ReadFromJsonAsync</code>؛ ويظهر الإلغاء
كـ <code dir="ltr">OperationCanceledException</code>، لا كرسالة مفقودة. وترمي الاستجابة غير
الناجحة <code dir="ltr">HttpRequestException</code>. والاستجابة الناجحة بلا ترجمة تُحل إلى
<code dir="ltr">null</code>.

استخدم Google عندما يكون الحجم منخفضاً والمحتوى ديناميكياً فعلاً ولا تلزم ذاكرة مؤقتة خارجية. لا
تستخدمه كمصدر كتالوج عالي الحركة؛ فكل بحث نداء شبكي مدفوع.

## ضوابط الكلفة والجودة

تكون الترجمة الآلية أرخص عندما لا تعمل أبداً. طبّق الضوابط بهذا الترتيب:

1. **لا تترجم عند الطلب عندما يستطيع كتالوج الاحتفاظ بالنتيجة.** ترجم في دفعة، وراجع المخرجات،
   واخدمها من مزوّد ملفات أو قاعدة بيانات. هذا يزيل أيضاً الخدمة البعيدة من مسار الطلب.
2. **قدّر قبل التشغيل.** استخدم <code dir="ltr">EstimateAsync</code> لرؤية المفاتيح المجانية
   والنداءات المدفوعة. والرقم المفاجئ يعني عادةً أن الذاكرة المؤقتة أو ذاكرة الترجمة باردة.
3. **ضع المصطلحات المعتمدة في مسرد.** تنجو المصطلحات المفروضة من إعادة الصياغة عبر حماية
   الرموز النائبة. والرمز الذي تُسقطه الترجمة الآلية لا يمكن استعادته؛ فيغيب المصطلح بدلاً من أن
   يكون خاطئاً بصمت، وهذا هو الفشل الأكثر أماناً.
4. **ضع الترجمات المعتمدة في ذاكرة الترجمة.** إعادة استخدام المطابقة التامة حتمية ومجانية.
   والذاكرة ليست أرشيف ترجمة آلية؛ نظّفها واعتنِ بها.
5. **حدّد الذاكرة المؤقتة.** ذاكرة Azure المؤقتة محدودة بـ 4096 إدخالاً؛ ويُطرد أقدم انتهاء تحت
   الضغط. لا تعاملها كمخزن ترجمة دائم.
6. **راجع السجل، لا الأعداد وحدها.** يخبرك <code dir="ltr">FailedCount</code> أن مقطعاً فشل؛
   ويخبرك <code dir="ltr">Entries</code> أي المفاتيح ولماذا.

مراجعة الجودة عملية، لا ميزة مزوّد. يعيد المزوّد نصاً دون الحكم عليه. وحلقة مراجعة عملية هي:
ترجمة دفعة إلى كتالوج تدريجي، وتشغيل أداة التكافؤ لاكتشاف المفاتيح المفقودة وانحراف العناصر
النائبة، وقيام مراجع أصلي بتحرير السلاسل في كتالوج التدريج، ثم تطبيق القيم المعتمدة عبر المخزن المحكوم أو
عملية إصدار الكتالوج المعتادة.

**مأزق:** افتراض أن العناصر النائبة تنجو من الترجمة الآلية. غالباً تنجو، لكن ليس بموثوقية. شغّل
فحص العناصر النائبة بعد كل دفعة ترجمة آلية. والقالب المترجم الذي فقد
<code dir="ltr">{0}</code> سيرمي أو يعرض خطأً وقت التشغيل.

**مأزق:** كتابة مخرجات الآلة مباشرة في ذاكرة الترجمة. الذاكرة هي خط الأساس المعتمد؛ وتلويثها يجعل
كل بحث مستقبلي يثق بنص غير مُراجَع.

**مأزق:** تفعيل معدل طلبات مرتفع ضد اشتراك محدود المعدل. محدد المعدل معطّل افتراضياً حفاظاً على
الإنتاجية. فعّله عمداً واضبط حجم دفعة يطابق حدود الاشتراك.

**مأزق:** التعامل مع <code dir="ltr">RequestTimeout</code> كمهلة لكل محاولة. إنها تحد المقطع كله،
بما فيه إعادة المحاولة والانتظارات. وسلسلة إعادة محاولة طويلة قد تستنفد الميزانية قبل بدء
المحاولة الأخيرة.

## مثال عملي: تعبئة مُراجَعة

يملك منتج 800 مفتاح إنجليزي ويريد مسودات عربية وبولندية. ولا يريد الفريق ترجمة عند الطلب.

1. تحل مهمة لمرة واحدة مزوّد Azure وتنشئ <code dir="ltr">TranslationBatchJob</code>.
2. تبلّغ <code dir="ltr">EstimateAsync</code> عن 800 مفتاح × ثقافتين، مع 120 إصابة من ذاكرة
   مؤقتة من تشغيل سابق و40 نداءً مدفوعاً. وتقسّم المهمة المفاتيح بنوافذ 100 لكل طلب.
3. يكتب <code dir="ltr">RunAsync</code> سجلاً. تفشل نافذة بولندية بمهلة؛ فتُعلَّم 18 إدخالاً
   <code dir="ltr">Failed</code>، والباقي <code dir="ltr">Translated</code> أو
   <code dir="ltr">Cached</code>. وتكتمل الدفعة.
4. يعيد الفريق محاولة المفاتيح الفاشلة فقط بعد إغلاق القاطع. والإدخالات الناجحة مخزّنة مؤقتاً ولا
   تكلّف شيئاً في المرة الثانية.
5. تُكتب قوالب السجل في كتالوج تدريجي. وتبلّغ أداة التكافؤ عن 12 انحراف عنصر نائب و3 مفاتيح
   مفقودة. يصلحها المراجعون.
6. تُطبَّق السلاسل المعتمدة على كتالوج وقت التشغيل عبر عملية الإصدار المعتادة. وتُحدَّث ذاكرة
   الترجمة بالقيم المُراجَعة فقط.
7. يخدم الإنتاج الكتالوج المنشور من مزوّد JSON. ومزوّد الترجمة غير مسجّل في الإنتاج إطلاقاً.

النقطة الأخيرة هي المهمة. كان المزوّد أداة وقت بناء، لا تبعية وقت تشغيل.
