# المفاتيح المكتوبة بقوة (strongly typed keys)

المفاتيح النصية مرنة ويسهل تمريرها، ولهذا بالضبط تفشل بصمت. يتحول الخطأ الإملائي إلى غياب وقت
التشغيل؛ ويترك تغيير الاسم مفاتيح قديمة في نصف مواضع النداء؛ ولا يكون لتغيير الكتالوج أثر يراه
المترجم. يحوّل مولّد المفاتيح (key generator) مفاتيح الكتالوج إلى حقول
<code dir="ltr">const string</code> كي تصبح تلك الإخفاقات أخطاء بناء.

يغطي هذا الفصل المولّد، والواجهة المولّدة، ومحلل قابلية التعريب (localizability analyzer)،
والتكوين الذي يربطها بمشروع.

## لماذا مفاتيح وقت الترجمة

تجعل المفاتيح المولّدة الأخطاء الإملائية أخطاء بناء، وتجعل تغييرات الأسماء تنتج أخطاء ترجمة على
مستوى الحل بدلاً من نصوص حرفية قديمة صامتة، وتتيح لبيئة التطوير عرض المفاتيح المتاحة. كما أنها
تمكّن إصلاح الكود (code fix) في محلل قابلية التعريب: عندما يطابق نص حرفي ثابتاً معروفاً تماماً،
يستطيع المحلل استبداله.

## إعداد المولّد

حزمة المولّد محلل وقت بناء (build-time analyzer). أشر إليها بأصول خاصة (private assets) كي لا
تصبح تبعية وقت تشغيل:

<div dir="ltr">

```xml
<ItemGroup>
  <PackageReference Include="Jeninnet.Localization.Generators.Keys" Version="1.0.0-preview.1" PrivateAssets="all" />
</ItemGroup>
```

</div>

صرّح بالكتالوجات كملفات إضافية. لا تُعتبر إلا الملفات التي تنتهي أسماؤها بـ
<code dir="ltr">.loc.json</code>:

<div dir="ltr">

```xml
<ItemGroup>
  <AdditionalFiles Include="Localization\en.loc.json" />
  <AdditionalFiles Include="Localization\ar.loc.json" />
</ItemGroup>
```

</div>

وإذا كانت الملفات نفسها تُخدم أيضاً وقت التشغيل، فانسخها إلى دليل الإخراج وسجّلها بمسارات صريحة:

<div dir="ltr">

```xml
<ItemGroup>
  <None Update="Localization\*.loc.json" CopyToOutputDirectory="PreserveNewest" />
</ItemGroup>
```

</div>

<div dir="ltr">

```csharp
var directory = Path.Combine(AppContext.BaseDirectory, "Localization");

services.AddJsonLocalizationProviders(builder => builder
    .AddCulture("en", Path.Combine(directory, "en.loc.json"))
    .AddCulture("ar", Path.Combine(directory, "ar.loc.json")));
```

</div>

يقبل تحميل المنشئ (builder overload) مسارات صريحة، لذا يمكن أن تكون ملفات المولّد المرجعية هي
ملفات وقت التشغيل نفسها. وإذا استخدمت تحميل الاصطلاح
(<code dir="ltr">AddJsonLocalizationProviders(baseDirectory, cultures)</code>)، فإنه يتوقع
<code dir="ltr">{culture}.json</code>، لا <code dir="ltr">{culture}.loc.json</code>؛ لا تضع ملفات
<code dir="ltr">.loc.json</code> في دليل يُكتشف تلقائياً كملفات ثقافات.

## عقد الإدخال

كل ملف <code dir="ltr">*.loc.json</code> كائن JSON مسطح يربط مفاتيح نصية بقوالب نصية. ويرفض
المولّد أي شيء خارج هذا الشكل كخطأ بناء:

- JSON مشوّه أو جذر غير كائن.
- مفاتيح أو قيم غير نصية.
- مفاتيح مكررة في ملف واحد.
- مفتاحان يُعقَّمان إلى المعرّف نفسه، أو مفتاح بلا محارف معرّف.
- مساحة أسماء مكوَّنة غير صالحة.

تبقى القوالب في المزوّد. ويصدر المولّد مفاتيح فقط، ولا يصدر نص الرسالة أبداً.

## شكل الواجهة المولّدة

لكتالوج يحتوي <code dir="ltr">App.Title</code> و<code dir="ltr">Cart.Items</code>، يصدر المولّد
وحدة ترجمة مكافئة لـ:

<div dir="ltr">

```csharp
// <auto-generated/>
#nullable enable
namespace MyApp.Generated;

public static partial class LocalizationKeys {
    public const string APP_TITLE = "App.Title";
    public const string CART_ITEMS = "Cart.Items";
    public static readonly string[] All = new string[] { "App.Title", "Cart.Items" };
}
```

</div>

الصف هو دائماً <code dir="ltr">public static partial class LocalizationKeys</code>، مع
<code dir="ltr">const string</code> واحد لكل مفتاح ومصفوفة <code dir="ltr">All</code> للمفاتيح
فقط. المعرّفات بحالة الثعبان العلوية (upper snake case)؛ وتقسّم الفواصل وحدود الحروف الكبيرة
والمختصرات الكلمات (<code dir="ltr">BookId</code> إلى <code dir="ltr">BOOK_ID</code>، و
<code dir="ltr">OrderID</code> إلى <code dir="ltr">ORDER_ID</code>)، ويحصل الرقم البادئ على شرطة
سفلية. الثوابت و<code dir="ltr">All</code> مرتبة ترتيبياً؛ والإخراج حتمي ومتطابق بايتياً لمدخل
ثابت. تساهم كتالوجات متعددة في صف واحد. ويسمح المعدّل <code dir="ltr">partial</code> بالمساعدات،
لكن الثوابت المولّدة لا تُحرَّر أبداً.

## تكوين مساحة الأسماء

بدون تكوين، تكون مساحة الأسماء <code dir="ltr">{AssemblyName}.Generated</code>. تجاوزها بخاصية
MSBuild واجعل تلك الخاصية مرئية للمترجم:

<div dir="ltr">

```xml
<PropertyGroup>
  <LocalizationKeysNamespace>MyApp.Localization</LocalizationKeysNamespace>
</PropertyGroup>
<ItemGroup>
  <CompilerVisibleProperty Include="LocalizationKeysNamespace" />
</ItemGroup>
```

</div>

عنصر <code dir="ltr">CompilerVisibleProperty</code> مطلوب؛ وبدونه يتراجع المولّد بصمت إلى
<code dir="ltr">{AssemblyName}.Generated</code>. وينجح البناء، لذا يسهل تفويت مساحة الأسماء
الخاطئة.

## تشخيصات وقت البناء

كل فشل للمولّد خطأ **بناء** مع ملف وسطر عندما يوفرهما المحتوى. ولا ينتج المحتوى المشوّه تخطياً
صامتاً أو صفاً جزئياً أبداً.

| التشخيص | المعنى |
|---|---|
| <code dir="ltr">JLNKEY001</code> | الكتالوج ليس JSON سليم الشكل، أو الجذر ليس كائن JSON. |
| <code dir="ltr">JLNKEY002</code> | إدخال لا يربط مفتاحاً نصياً بقالب نصي. |
| <code dir="ltr">JLNKEY003</code> | المفتاح نفسه يتكرر أكثر من مرة في ملف كتالوج واحد. |
| <code dir="ltr">JLNKEY004</code> | مفتاحان متمايزان يُعقَّمان إلى معرّف C# نفسه. |
| <code dir="ltr">JLNKEY005</code> | مفتاح لا يحتوي محارف معرّف. |
| <code dir="ltr">JLNKEY006</code> | مساحة الأسماء المكوَّنة ليست معرّف C# منقطاً صالحاً. |

تعامل مع هذه التشخيصات كتحقق من الكتالوج. البناء الأحمر يعني أن مجموعة المفاتيح المرجعية غامضة
أو مشوّهة، وهذا أفضل من اكتشاف ذلك وقت التشغيل.

## استخدام المفاتيح

<div dir="ltr">

```csharp
var text = await localizer.LocalizeAsync(
    LocalizationKeys.CART_ITEMS,
    new Dictionary<string, object?> { ["count"] = count },
    CultureInfo.CurrentUICulture);
```

</div>

الثوابت سلاسل عادية وتعمل مع <code dir="ltr">LocalizeWithContextAsync</code> و
<code dir="ltr">LocalizePluralAsync</code>، لكن المولّد لا يرمّز السياق أو اقتران الجمع. ولزوج
الجمع، عرّف المفتاحين ومرّر الثابتين.

## محلل قابلية التعريب

تضع حزمة <code dir="ltr">Jeninnet.Localization.Analyzers.Localizability</code> علامة على النصوص
الموجهة للمستخدم المكتوبة مباشرةً، كي ينقلها المؤلفون إلى خط الأنابيب وقت التأليف. وتشخيصه
الوحيد هو <code dir="ltr">JLNLOC001</code>.

تشمل الأشكال الموسومة إسنادات نص واجهة المستخدم (<code dir="ltr">control.Text</code> و
<code dir="ltr">Title</code> و<code dir="ltr">Header</code> و<code dir="ltr">Content</code> و
<code dir="ltr">Caption</code> و<code dir="ltr">ToolTip</code> و
<code dir="ltr">PlaceholderText</code>)، وإدخالات <code dir="ltr">ViewData</code>/
<code dir="ltr">ViewBag</code>، و<code dir="ltr">MessageBox.Show</code>، ورسائل الاستثناءات،
ورسائل التحقق (<code dir="ltr">AddModelError</code> و<code dir="ltr">ErrorMessage</code> و
<code dir="ltr">Display(Name)</code>)، ورسائل مشكلات API. أما المعرّفات والتسجيل وتأكيدات
الاختبارات والمهيّئات المحلية والسلاسل الفارغة والتراكيب غير المفتاحية فصامتة عمداً.

الخطورة الافتراضية مخفية (مستوى اقتراح المحرر). فعّل التحذيرات أو الأخطاء عبر
<code dir="ltr">LocalizabilitySeverity</code> (<code dir="ltr">suggestion</code> و
<code dir="ltr">warning</code> و<code dir="ltr">error</code>) المعلنة مرئيةً عبر
<code dir="ltr">&lt;CompilerVisibleProperty Include="LocalizabilitySeverity" /&gt;</code>، أو
عبر <code dir="ltr">dotnet_diagnostic.JLNLOC001.severity = warning</code> في
<code dir="ltr">.editorconfig</code>. ويفوز <code dir="ltr">.editorconfig</code> عند التعارض.
ويعمل الكبت القياسي: <code dir="ltr">#pragma</code> أو
<code dir="ltr">[SuppressMessage]</code> أو قسم لكل مجلد.

### إصلاح الكود

عندما يطابق النص الموسوم ثابت <code dir="ltr">const string</code> في صف
<code dir="ltr">*Keys</code> — مكتوباً يدوياً أو مولّداً — يستبدل إصلاح الكود النص بمرجع مؤهل
بالكامل إلى ذلك الثابت. أما النصوص بلا ثابت مطابق فلا تحصل على إصلاح. ولا يستخرج المحلل السلاسل
إلى كتالوجات؛ فذلك قرار تأليف صريح، وأداة التكافؤ تبلّغ عن الفجوات بدلاً من كتابتها.

**مأزق:** إصلاح الكود ليس سير عمل ترجمة. استبدال نص حرفي بثابت يجعل موضع النداء آمناً من حيث
النوع، لكن المفتاح ما زال يحتاج إدخالاً في الكتالوج لكل ثقافة مخدومة. شغّل أداة التكافؤ بعد
تطبيق الإصلاحات.

## مثال عملي: من الكتالوج إلى موضع النداء

1. أنشئ <code dir="ltr">Localization/en.loc.json</code> مع
   <code dir="ltr">App.Title</code> و<code dir="ltr">Cart.Items</code>.
2. أضفه كـ <code dir="ltr">AdditionalFile</code>، وعيّن
   <code dir="ltr">LocalizationKeysNamespace</code>، وأضف
   <code dir="ltr">CompilerVisibleProperty</code> المطابق.
3. ابنِ. يحتوي الصف على <code dir="ltr">APP_TITLE</code> و
   <code dir="ltr">CART_ITEMS</code>.
4. سجّل الملف نفسه مع مزوّد JSON باستخدام تحميل المنشئ الصريح.
5. استخدم <code dir="ltr">LocalizationKeys.CART_ITEMS</code> في موضع النداء.
6. أضف الكتالوج العربي. يولّد المولّد اتحاد المفاتيح؛ وتبلّغ أداة التكافؤ عن الترجمات المفقودة.

تتبع المفاتيح المولّدة كل كتالوج مصرَّح به، لا الترجمات: فالمفتاح الموجود فقط في
<code dir="ltr">ar.loc.json</code> يولّد ثابتاً أيضاً.

## سلوك وقت البناء والتغليف

تُشحن الحزمة كأصل محلل تحت <code dir="ltr">analyzers/dotnet/cs</code> مع
<code dir="ltr">DevelopmentDependency=true</code>، وتستهدف <code dir="ltr">netstandard2.0</code>
لكل مضيف Roslyn، ولا تصبح تبعية وقت تشغيل أبداً. التوليد تزايدي (incremental): الكتالوجات غير
المتغيرة تعيد استخدام نتائج تحليل مخزّنة، وخطوة إصدار واحدة تنتج الصف. وتستخدم حزمة المحلل نموذج
التغليف نفسه.

## مآزق

**مأزق:** إضافة الكتالوج كـ <code dir="ltr">Content</code> بدلاً من
<code dir="ltr">AdditionalFiles</code>. يُنسخ الملف أو يُخدم، لكن المولّد لا يراه أبداً، فلا
تُنتج ثوابت. ولا يوجد خطأ؛ ببساطة يكون الصف غائباً أو قديماً.

**مأزق:** نسيان <code dir="ltr">CompilerVisibleProperty</code> لمساحة الأسماء. ينجح البناء
وتهبط الثوابت في <code dir="ltr">{AssemblyName}.Generated</code>، وقد لا تكون مساحة الأسماء
التي تتوقعها.

**مأزق:** توقع أن يتحقق المولّد من الترجمات. إنه يتحقق من كتالوجات المفاتيح التي يقرأها. أما
الثقافات المفقودة وانحراف العناصر النائبة والمفاتيح غير المستخدمة فهي نتائج أداة التكافؤ، لا
تشخيصات المولّد.

**مأزق:** وضع ملفات <code dir="ltr">.loc.json</code> في دليل وقت تشغيل يُكتشف تلقائياً. يعامل
تحميل اصطلاح JSON كل جذر ملف <code dir="ltr">*.json</code> كرمز ثقافة، لذا
<code dir="ltr">en.loc.json</code> ليس ثقافة <code dir="ltr">en</code>. استخدم مسارات منشئ
صريحة أو أبقِ مدخلات المولّد منفصلة عن كتالوجات وقت التشغيل.

**مأزق:** التعامل مع بناء أخضر كتغطية تعريب. تثبت مفاتيح وقت الترجمة أن المفتاح موجود في كتالوج
مصرَّح به، لا أنه موجود في كل لغة. استخدم
[التكافؤ وبوابات الجودة](13-parity-and-quality-gates.md).
