# Jeninnet.Localization.Generators.Keys

`Jeninnet.Localization.Generators.Keys` is a Roslyn incremental source generator that turns flat `*.loc.json` catalogs into compile-time key constants. It industrializes the hand-maintained `ReferenceKeys` pattern: typos become build errors, renames propagate through compilation, and content/key drift is caught at compile time. The generated class contains keys only - templates stay in providers and are never baked into code. See [Strongly typed keys](../../../docs/en/02-guides/05-strongly-typed-keys.md) for the end-to-end workflow.

## Installation

```bash
dotnet add package Jeninnet.Localization.Generators.Keys
```

Reference it as a build-time analyzer:

```xml
<ItemGroup>
  <PackageReference Include="Jeninnet.Localization.Generators.Keys"
                    Version="1.0.0"
                    PrivateAssets="all" />
</ItemGroup>
```

The package ships a single `analyzers/dotnet/cs` asset with `DevelopmentDependency=true`; it never becomes a runtime dependency. The project targets `netstandard2.0` so the generator loads in every Roslyn host.

## Registration

Declare the catalogs as `AdditionalFiles`. Only file names ending in `.loc.json` are considered:

```xml
<ItemGroup>
  <AdditionalFiles Include="Localization\en.loc.json" />
  <AdditionalFiles Include="Localization\ar.loc.json" />
</ItemGroup>
```

If the same files are also served at runtime, copy them to the output directory and register the runtime provider with explicit paths:

```xml
<ItemGroup>
  <None Update="Localization\*.loc.json" CopyToOutputDirectory="PreserveNewest" />
</ItemGroup>
```

```csharp
services.AddJsonLocalizationProviders(builder => builder
    .AddCulture("en", Path.Combine(AppContext.BaseDirectory, "Localization", "en.loc.json"))
    .AddCulture("ar", Path.Combine(AppContext.BaseDirectory, "Localization", "ar.loc.json")));
```

There is no service registration for the generator itself; it runs during compilation.

## Configuration

Without configuration, the generated namespace is `{AssemblyName}.Generated`. Override it with an MSBuild property that is visible to the compiler:

```xml
<PropertyGroup>
  <LocalizationKeysNamespace>MyApp.Localization</LocalizationKeysNamespace>
</PropertyGroup>
<ItemGroup>
  <CompilerVisibleProperty Include="LocalizationKeysNamespace" />
</ItemGroup>
```

The `CompilerVisibleProperty` item is required. Without it the property does not reach the analyzer; the build still succeeds with the default namespace. An invalid dotted identifier produces `JLNKEY006`.

The only other input contract is the file suffix and shape: a flat JSON object mapping string keys to string templates. The generator follows every declared catalog, so a key present only in a translation file still generates a constant.

## Usage

Input `Localization/en.loc.json`:

```json
{
  "App.Title": "Bookstore",
  "Cart.Items": "You have {count} items."
}
```

Generated `LocalizationKeys.g.cs`, equivalent to:

```csharp
// <auto-generated/>
#nullable enable
namespace MyApp.Generated;

public static partial class LocalizationKeys {
    public const string APP_TITLE = "App.Title";
    public const string CART_ITEMS = "Cart.Items";
    public static readonly string[] All = new string[] { "App.Title", "Cart.Items" };
}
```

```csharp
var text = await localizer.LocalizeAsync(
    LocalizationKeys.CART_ITEMS,
    new Dictionary<string, object?> { ["count"] = 3 },
    CultureInfo.CurrentUICulture);
```

Identifiers are upper snake case. Separators and camel/acronym boundaries split words (`BookId` becomes `BOOK_ID`, `OrderID` becomes `ORDER_ID`), and a leading digit gains an underscore. Constants and `All` are ordinal-sorted. Multiple catalogs contribute to one class. The output is deterministic and byte-identical for fixed inputs.

## Behavior and limits

- **Input contract.** A flat JSON object of string keys to string templates. Malformed JSON, a non-object root, non-string keys or values, duplicate keys in one file, identifier collisions, keys with no identifier characters, and an invalid namespace are build errors. Nothing is emitted when any diagnostic is reported.
- **No silent skip.** Every failure carries a file and line where the content supplies one. There is no partial class and no warning-only path.
- **Keys only.** The generated class never contains message text. It exposes one `const string` per key plus the keys-only `All` array.
- **Determinism.** Catalogs are processed in ordinal path order, keys are ordinal-sorted, and no timestamps or machine data are emitted. Incremental parsing reuses results for unchanged catalogs.
- **Multiple catalogs.** Catalogs are combined into one key set. Duplicate keys are rejected within a single file; the same key may appear in several catalogs.
- **Generated hint.** The compilation unit is added as `LocalizationKeys.g.cs`.
- **No runtime behavior.** The generator does not read catalogs at runtime, does not select a provider, and does not validate translations. Missing cultures and placeholder drift are parity-tool findings.
- **Diagnostics.** All six are errors:

| ID | Meaning |
|----|----|
| `JLNKEY001` | The catalog is not well-formed JSON, or the root is not a JSON object. |
| `JLNKEY002` | An entry does not map a string key to a string template. |
| `JLNKEY003` | The same key occurs more than once in one catalog file. |
| `JLNKEY004` | Two distinct keys sanitize to the same C# identifier. |
| `JLNKEY005` | A key contains no identifier characters. |
| `JLNKEY006` | The configured namespace is not a legal dotted C# identifier. |

## AOT and trimming

**Build-time only.** The project targets `netstandard2.0` and runs in the compiler/Roslyn host, not in the published application, so the runtime AOT (Ahead-of-Time)/trimming contract does not apply. See [AOT and trimming](../../../docs/en/aot-and-trimming.md) for the contract and exclusions.
