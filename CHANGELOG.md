# Changelog

All notable changes to the Jeninnet.Localization solution are documented in this file.

The format is inspired by Keep a Changelog. The solution has **not been publicly released**: every entry below is under active development, and the version numbers in the repository are development placeholders, not release declarations.

## [Unreleased]

### Added

- Public third-party notice (`THIRD-PARTY-NOTICES.md`): CLDR/Unicode attribution, ICU syntax attribution, runtime dependency inventory, Oracle MySQL's GPL-2.0-only-with-Universal-FOSS-exception terms, and license references. Every package now ships the notice, and the documentation site exposes the same content.
- Host culture integrations (`Jeninnet.Localization.Integrations.Avalonia`, `.Maui`, and `.WinUI`): a shared culture contract with configurable supported cultures and default culture, platform persistence (file for Avalonia, MAUI preferences, and Windows application data), `HostCultureService` initialization/set/reset, change notifications, RTL state and platform `FlowDirection` helpers, DI registration that lets a host store win, public-API baselines, Windows host composition tests, and sample hosts sharing English/Arabic content. MAUI targets `net10.0`; WinUI targets `net10.0-windows10.0.19041.0`; Avalonia follows the `net8.0`/`net9.0`/`net10.0` matrix.
- Opt-in ICU (International Components for Unicode) MessageFormat templates through `IcuMessageFormatter` (`ICultureAwareMessageFormatter`): `plural` (explicit values, offsets, `#`), `select`, `selectordinal`, `number`/`date`/`time`, and nested messages, formatted in the requested culture. Registration is the opt-in; templates without ICU constructs render exactly as before, and malformed templates fail with a descriptive `FormatException`.
- CLDR (Common Locale Data Repository) plural-category engine (`PluralRules`/`PluralCategory` in Abstractions): cardinal rules for 51 languages (including 6-form Arabic, Russian/Ukrainian/Belarusian, Czech/Slovak, Polish, Lithuanian, Slovenian, Serbo-Croatian, Romanian, Hebrew, Maltese, Irish, Welsh, Gaelic) and English ordinals, verified against CLDR-derived test vectors.
- Gettext-style plural/context API on `IMessageLocalizer`: `LocalizePluralAsync` (singular/plural key pair + count, form selected by the CLDR cardinal category in the requested culture; available-form fallback, otherwise `null`) and `LocalizeWithContextAsync` (`msgctxt`-compatible `context + EOT + key` namespacing so identical keys stay independent and  PO (Portable Object) catalogs interoperate). Existing `null` miss semantics are unchanged.
- HTML-safe localization (XSS-safe views): `HtmlSafeMessageFormatter` in Core encodes string arguments with `HtmlEncoder.Default` while trusted template markup passes through (numeric/boolean/date values pass through by identity so ICU selection composes), and `HtmlMessageLocalizer`/`HtmlMessageLocalizer<T>` in the MVC integration implement the framework `IHtmlLocalizer`/`IHtmlLocalizer<T>` over the canonical pipeline (no duplicate fallback; `LocalizedHtmlString` results; opt-in `AddHtmlMessageLocalizer()`).
- View-scoped Razor localization (`IViewLocalizer` parity): `ViewMessageLocalizer` in the MVC integration resolves the executing view path through the canonical pipeline — view-scoped entry first (full culture fallback), then the shared entry (exactly the plain pipeline result when no scoped entry exists) — composing the  HTML-safe bridge; opt-in `AddViewMessageLocalizer()`, and the MVC sample views now resolve through it with unchanged output.
- Blazor localization integration: `AddBlazorLocalization` with a circuit-scoped culture service for Blazor Server (`AddBlazorServerLocalization`; per-circuit request-culture seeding via `CircuitHandler`, ambient culture never mutated so concurrent circuits cannot bleed into each other) and a static single-user scope for client-side hosts (`AddBlazorWasmLocalization`, which also enforces the WASM-compatible provider subset through the new `IWasmCompatibleMessageProvider` marker — file/DB providers are rejected with an actionable error; the Memory provider declares the marker). The culture-switch service persists through a host-wired `IBlazorCultureStore` (shipped: RequestLocalization-cookie and local-storage stores using the canonical cookie format) over a self-contained `IJSRuntime` bridge; the Blazor Server and Blazor Hybrid sample hosts migrated to the package with their hand-rolled culture glue deleted.
- JavaScript resource delivery: `MapJavaScriptLocalization()` maps a versioned minimal-API `GET` endpoint (default `/localization/v1/{culture}`) that serves the explicit allow-list of message templates as a flat `{key: template}` JSON payload with a quoted strong content-hash ETag (SHA-256 (Secure Hash Algorithm, 256-bit)) and configurable `Cache-Control` — matching `If-None-Match` returns `304` (weak comparison, `*` supported). `JavaScriptResourcePayloadBuilder` also exports the identical bytes as `{culture}.json` files for build-time embedding in SPA/WASM (WebAssembly)/offline shells. Templates are serialized with the JavaScript-safe System.Text.Json encoder, keys resolve exact-culture through the canonical provider (no fallback re-implementation; missing keys omitted), disallowed keys are never requested so they cannot leak, and unserved cultures return `404`.
- Pipeline observability hooks: `LocalizationDiagnostics` in Abstractions exposes one stable `ActivitySource` and one `Meter` (both named `Jeninnet.Localization`) using BCL (Base Class Library) `System.Diagnostics.*` only — no OpenTelemetry package is referenced and every emission is listener-guarded, so hosts without diagnostics pay nothing. Traces: a `localization.lookup` activity per localizer call (key/culture/found tags, template text never tagged) with a `localization.fallback.step` child per provider query along the canonical fallback chain. Metrics: `localization.lookup.hits`/`misses`/`duration` (ms) and `localization.fallback.steps`, plus the Azure provider's `localization.translation.requests`, `localization.translation.cache.hits`/`misses`, and `localization.translation.duration` (ms). Consumers opt in with `AddSource("Jeninnet.Localization")` / `AddMeter("Jeninnet.Localization")` on the OTel (OpenTelemetry) SDK side.
- Health checks: `AddLocalizationHealthChecks(...)` registers `jeninnet-localization-provider` (explicit probe key via the canonical `IMessageProvider`: resolved → Healthy, unserved → Degraded, throws → Unhealthy with the exception type in data) and `jeninnet-localization-store` (reachability through `ILocalizationStore.GetSupportedCulturesAsync`: reachable → Healthy, empty → Degraded, throws → Unhealthy). Descriptions and data never contain template text. The package depends on `Microsoft.Extensions.Diagnostics.HealthChecks` + Abstractions only (no ASP.NET Core framework coupling).
- Term-level control for machine translation: per-culture glossaries (`MessageGlossary`/`GlossaryTerm` in Abstractions) force term translations through placeholder protection, so a forced term survives an MT paraphrase; conflicting registrations are reported, never applied silently. An exact-match translation memory (`ITranslationMemory`/`InMemoryTranslationMemory`) short-circuits paid API calls. Both layers are configured through `AzureTranslationOptions` (snapshot discipline preserved) and compose with the existing cache, single-flight, refresh, and event semantics — resolution order: memory → glossary-protected machine translation → cache write-back.
- Formal resilience for the Azure translation provider (hand-rolled BCL-only, no policy-library dependency): per-chunk total timeout (always surfaces as cancellation), idempotent-safe retries with exponential backoff + jitter, a circuit breaker with single half-open probes (`BrokenCircuitException` on fail-fast rejection), and a client-side token-bucket rate limiter. Eight `AzureTranslationOptions` knobs with safe defaults; breaker state is observable through the existing acquisition events; cache semantics unchanged.
- Governed batch translation for catalog backfills (`TranslationBatchJob`): keys × cultures with per-window `IProgress<T>` reporting, cancellation preserving a partial ledger (`TranslationBatchCancelledException`), side-effect-free dry-run estimates that count cache/translation-memory hits as free, and a per-key ledger (`Translated`/`Cached`/`Failed` + reason) where chunk failures never abort the batch. Reuses the provider pipeline (no bypass, no writes of its own); persistent apply lives with.
- Request-localization bridge: `AddLocalizationRequestCultures(...)` populates `RequestLocalizationOptions` from the explicit overrides or `ILocalizationStore.GetSupportedCulturesAsync` (store order, deduplicated; default culture always served; deterministic default-culture-only fallback when no store is registered or the store is unreachable; fail-fast with an actionable error when the store reports zero cultures or an unrecognized name) and installs a served-culture provider composition — route → query string → cookie → `Accept-Language`. The framework providers stay the mechanism; `RouteValueRequestCultureProvider` supplies the route source the framework lacks and `ServedCultureRequestCultureProvider` narrows any provider result to the served set (exact name, then the framework-configured parent fallback), so unserved requests fall back deterministically to the default culture. One registration call yields a working `app.UseRequestLocalization()` configuration; the package depends on Abstractions only (no Core edge) and never mutates the ambient culture.
- `IHtmlLocalizerFactory` parity: `HtmlMessageLocalizerFactory` in the MVC integration completes the HTML-localizer bridge to the full BCL surface — `Create(Type)` and `Create(baseName, location)` return the same key-based pipeline bridge the generic `IHtmlLocalizer<T>` registration yields (HTML-encoded arguments, canonical fallback, per-call UI-culture capture), registered by `AddHtmlMessageLocalizer()` in place of the framework factory. The HTML bridge has no resource-set dimension, so no type→resource-set mapping is duplicated — Core's `CustomStringLocalizerFactory` remains the single mapping owner.
- Razor `<loc>` tag helper: `LocalizeTagHelper` in the MVC integration localizes inline view content without a code-behind lookup — `<loc key="Cart.Title">Shopping Cart</loc>` resolves the key through the canonical pipeline via the  bridge (templates trusted, `arguments="@expr"` values HTML-encoded, per-call UI culture) and falls back to the authored element body on a miss. The body is emitted through the Razor content pipeline (static markup passes through, expressions stay single-encoded); the `<loc>` element and its attributes are removed from the output. The MVC reference sample now uses the tag helper.
- Translator notes per key: `IResourceAdminStore` gains the governed note surface — `GetNoteAsync`/`GetNotesAsync` (reads) and `SetNoteAsync`/`DeleteNoteAsync` (mutations, dry-run, conflicts, validation) — persisted as one language-agnostic note per (resource set, key) in the EF store (`StringNotes`). Notes follow the key lifecycle atomically (rename moves, last-culture-row deletion and set delete remove, set rename moves; no orphan rows), every direct or cascaded note change bumps the catalog version and appends a redacted, hash-chained audit record (empty culture for note rows; the string replay journal stays template-only), and the XLIFF (XML Localization Interchange File Format) interchange carries `<note category="translator">` on export (`translatorNotes` map, flat keys) and surfaces parsed notes per key in the import report (catalog files have no note storage; store application is the caller's governed `SetNoteAsync` step).
- CSV catalog interchange: `Jeninnet.Localization.Interchange.Csv` exports and imports catalogs as RFC 4180 CSV (`key,culture,value,note`; UTF-8 (Unicode Transformation Format, 8-bit) with BOM (Byte Order Mark); strict parsing with file/line diagnostics) for spreadsheet workflows — validate-then-apply with the shared conflict-policy vocabulary (`Unchanged`/`Updated`/`Skipped`/`UnknownKey`/`StaleSource`/`UnsupportedKey`), dry-run previews, translator-note round-trip in the `note` column (surfaced in the report, never applied to files), and byte-identical no-change round-trips. The interchange family gains a shared contract home (`Jeninnet.Localization.Interchange.Abstractions`: `CatalogKeyStatus` plus the internal catalog file codec both formats use); XLIFF's status type is renamed `CatalogKeyStatus` accordingly (canonical rename, unreleased repo).
- ResX catalog interchange: `Jeninnet.Localization.Interchange.ResX` exports and imports canonical ResX 2.0 files (VS header, strings + comments) for the ResX editor/translator ecosystem — validate-then-apply with the shared status vocabulary (`Unchanged`/`Updated`/`Skipped`/`UnknownKey`/`UnsupportedKey` for non-string entries; `StaleSource` documented as not representable), dry-run previews, translator notes as comments (surfaced in the report, never applied to files), file/line diagnostics for malformed or foreign files, and byte-identical no-change round-trips. The classic BCL `ResXResourceWriter`/`ResXResourceReader` are Windows-Desktop-only on net10.0, so the package ships a hand-rolled canonical writer/reader; the runtime `Providers.ResX` is untouched.
- PO file interchange: `Jeninnet.Localization.Interchange.Po` exports and imports standard gettext PO text (`msgid`/`msgstr`, `msgctxt` contexts, `msgid_plural`/`msgstr[n]` plural tables, `#.` translator notes, optional caller-supplied `Plural-Forms` header written verbatim) for Poedit/msgcat-style workflows — validate-then-apply with the shared status vocabulary (`Unchanged`/`Updated`/`Skipped` for empty/fuzzy/`UnknownKey`/`UnsupportedKey`; `StaleSource` documented as not representable), dry-run previews, file/line diagnostics, byte-identical no-change catalog round-trips, and provider-interop vector tests proving an exported file serves the same templates and plural semantics through the runtime `PoMessageProvider` (which stays untouched).
- ICU percent style and the documented `::` skeleton subset: `IcuMessageFormatter` now formats the named `percent` number style (`P0`, ICU's default percent precision) and `::` skeletons — `percent`, `currency/XXX` (ISO code; symbol resolved from BCL `RegionInfo` data), fixed precision (`.00`), and numeric date (`y`/`M`/`d`) / time (`H`/`h`/`m`/`s`/`a`/`z`/`S`) skeletons mapped deterministically to `NumberFormatInfo`/`DateTimeFormatInfo` facts (locale date order and separators derived from the culture's short-date pattern; bidi marks stripped). Excluded constructs (compact `K`/`KK`, variable precision, text months, weekday, mixed date+time skeletons) fail with precise `FormatException`s — no silent fallback; named styles and existing behavior are byte-identical (regression suite green).
- Gettext `.mo` binary catalog reader: `Providers.Po` now serves compiled GNU MO (Machine Object) catalogs behind the same provider contract — `MoParser` handles both endiannesses (magic `0x950412de`/`0xde120495`), revisions 0.x/1.x (hash table ignored), bounds-checked string tables, strict UTF-8, EOT (End of Transmission) contexts, and NUL-joined plural originals/translations, feeding the new shared `PoCatalogBuilder` so keys, contexts, plurals, headers, and `Plural-Forms` validation have a single owner across both carriers (`.po` behavior byte-identical). Reader selection is explicit and deterministic (`PoCatalogFormat { Auto, Po, Mo }` + `PoLocalizationOptions.Format`; `Auto` picks by `.mo` extension, no content probing — the default location provider stays `.po`-only; forced readers cover extensionless files; undefined values fail fast at construction). Malformed binaries throw `PoParseException` naming the violated structure (line 0) and never yield partial tables; hot reload and lookup/fallback semantics are unchanged. This reopens the `.mo`-reading half of 's conscious non-proposal with recorded maintainer go-ahead; the `msgfmt` toolchain dependency and `.mo` writing remain rejected.
- Markdown-aware resources: `MarkdownMessageFormatter` in Core renders a documented CommonMark subset in trusted templates — emphasis, strong, single-backtick code spans, `[label](destination)` links, and simple unordered/ordered lists (mixed unordered markers merge; `start` emitted for non-1 first markers), with backslash escapes for the subset delimiters. The template renders first and the inner formatter substitutes afterwards, so argument values are never parsed as Markdown or HTML: `new MarkdownMessageFormatter()` defaults its inner to `HtmlSafeMessageFormatter`, composes with ICU (`new MarkdownMessageFormatter(new HtmlSafeMessageFormatter(new IcuMessageFormatter()))`) and with the MVC `IHtmlLocalizer` bridge over pre-encoded arguments (`new MarkdownMessageFormatter(new DefaultMessageFormatter())`, single encoding). Raw HTML in the source is inert by default (text nodes HTML-encoded; `allowRawHtml: true` opts into trusted passthrough), code-span content is always encoded, and link destinations are always attribute-encoded. Constructs outside the subset (headings, blockquotes, fences, tables, images, entities, nested lists, autolinks, …) render literally — never silently mangled — with the subset, trust model, and exclusions documented in the type remarks and Core README. Hand-rolled, BCL-only; no pipeline, provider, store, or schema change.
- Placeholder/argument parity validation: `Tools.Keys` gains the `placeholder-drift` finding kind — a catalog-internal cross-culture comparison for keys served locally by at least two cultures, with file/line/key/culture precision. The reference set is the default culture's when it serves the key locally (otherwise the ordinal-first serving culture's); only locally-serving cultures are compared (fallback cultures stay the completeness matrix's concern). Identifiers come from a balanced-brace, ICU-aware scan: an ICU construct (`{n, plural, …}`, `{gender, select, …}`) contributes only its outer argument name — branch-internal placeables are conditional at runtime and never count, so differing plural/select branch counts across languages are not drift — while any other `{…}` contributes its content verbatim (the canonical `DefaultMessageFormatter` parameter key). Sets are ordinal: named-argument reordering is never drift, positional `{0}`/`{1}` drops and additions are caught, empty (untranslated) templates are skipped, and the existing `--exclude key` / `--exclude culture:key` surface applies. The JSON report schema is bumped to `schemaVersion: 2` (new kind + `summary.placeholderDrifts`; README example updated; exit codes unchanged), and the documented dogfood command over the sample corpus stays green with the new check enabled. The tool remains report-only, standalone (BCL + Roslyn), and its assembly API surface is unchanged (all types internal).
- Code-first resource declaration and synchronization: `[LocalizedResource("ResourceSet", "Key", "Default template")]` declares message keys in code; `ResourceDeclaration` is the canonical input and `LocalizedResourceDiscovery` (every method `RequiresUnreferencedCode`-annotated — trimmed deployments pass explicit declarations) discovers them deterministically. `ResourceSynchronizer` (`IResourceSynchronizer`, Core) applies declarations through the  governed path only — validate-then-apply, the caller's actor on every audit entry, adds only by default (differing values `Skipped` unless `AllowUpdates`), non-default culture values never modified (missing target cultures `Skipped` with fallback preserved, or created empty as untranslated placeholders with `CreateMissingTargetCultures`), declared notes applied on create and upserted only with `AllowUpdates`, explicit mapped renames through the governed cross-culture atomic rename, per-key conflict reporting that never aborts other keys, dry-run previews that mutate and audit nothing, idempotent second runs (`Unchanged`, zero mutations, zero audit entries), and no delete. The per-entry report (`ResourceSynchronizationReport`: created/updated/unchanged/skipped/conflict/renamed with details and counts) is the explicit surface hosts schedule; auto-translation, implicit background adds, and any UI stay out of scope. No new write mechanism, no dependency change (architecture tests green); the  exclusion list records the annotated discovery surface.
- Blazor browser-language default culture: `BlazorLocalizationOptions.DetectBrowserLanguage` (opt-in, default off) extends `BlazorCultureService.InitializeAsync` with the client-side negotiation chain — **stored choice → browser language → configured default**. When no stored choice applies, `navigator.languages` (falling back to `navigator.language`) is read through the existing self-contained `BlazorCultureJsInterop` bridge (new `ReadBrowserLanguagesAsync`; still no host JavaScript file) and mapped to `SupportedCultures` — exact tag first, then the browser tag's parent chain (`de-DE` → `de`) — applying the first match's canonical supported name; a less specific browser tag never matches a more specific supported entry, and with an empty supported list the first recognized preference applies. No match leaves the culture unapplied so `DefaultCulture` applies deterministically. Detection is static-scope only (`BlazorLocalizationMode.Wasm`; server mode stays seeded from the resolved request culture and ignores the option), read-only (never persisted — the store keeps explicit user choices only), and best-effort (interop unavailability, JS errors, or an empty language list mean no detection, never an exception; cancellation still propagates). The DI (Dependency Injection) composition resolves the bridge only when the host provides `IJSRuntime`; detection-disabled and server hosts are byte-identical to before. No new dependency; the integration stays an adapter over `CultureInfo`, DI, and `IJSRuntime`.
- Cancellation-aware canonical async contracts: `IMessageProvider.GetMessageTemplateAsync` and `IMessageLocalizer.LocalizeAsync` accept an optional final `CancellationToken`, propagated through the localization pipeline and provider implementations.
- A store-backed `IStringLocalizer` bridge that resolves resource sets on every lookup instead of permanently binding to the first resource set.
- Bounded TTL (Time To Live) caching with per-key single-flight coalescing and generation-based refresh for the Azure translation provider.
- Real-engine runtime verification for the EF Core localization store (environment-gated).
- Community and CI infrastructure: `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `ROADMAP.md`, the `.github` community files (`CODEOWNERS`, `SECURITY.md`, `SUPPORT.md`, `COMMUNITY_GUIDELINES.md`, pull-request and issue templates, Dependabot and funding configuration), five GitHub Actions workflows (`ci`, `docs-build`, `nuget-publish`, `sonarcloud`, `auto-approve-dependabot`), and the supporting tooling — `scripts/badges` (gate-driven README reliability badges), `scripts/docs` (documentation link and README-claims gates), `scripts/sonar` (local SonarCloud preview), plus `coverlet.collector` so the coverage collector and Sonar coverage paths produce OpenCover reports. The `.github`, `scripts`, and `docs` trees are surfaced in the solution file, and the README shows the generated badges.
- Package validation from the consumer's side: `consumers/Jeninnet.Localization.Consumer` is a real application that resolves the libraries from the **packed packages** in the local feed (`artifacts/`, populated by `dotnet pack`) — never through project references — and exercises the canonical pipeline over the Memory provider (keyed by the generator-emitted constants), the per-culture JSON catalogs, and the CSV translator hand-off; `consumers/Jeninnet.Localization.Consumer.Tests` drives that scenario and validates the package set itself: inventory against the committed public-API baselines, payload and repository metadata, the analyzer/code-fix/generator/tool asset layout, and the dependency closure inside the feed. The consumers live in their own solution (`Jeninnet.Localization.Consumers.slnx`) so the repository solution still builds without a pack step; CI runs the pack → restore → build → test sequence in the `consumer-validation` job, and a dedicated global-packages folder with a pack-time invalidation target keeps the validation honest while the solution version stays constant.

### Changed

- **Breaking:** resource audit lines now take parameter objects: `ResourceAdminAuditEventArgs` accepts a `ResourceAdminAuditContext` (timestamp, actor, operation) plus a `ResourceAdminAuditRow` (resource set, culture, key, rename target, entry identity) and the old/new template values, and `ResourceHistoryRecord` accepts the same context/row pair plus sequence, version, and the redacted value hashes. The previous 10- and 12-parameter public constructors are removed; direct constructor callers must switch to the grouping types (all properties and behavior are unchanged).
- The PO text grammar is now one implementation compiled into two packages: `src/shared/PoTextParsing.cs` is a linked source file included by both `Providers.Po` and `Interchange.Po`, removing the 50 duplicated lines the quality gate measured between the provider parser and the interchange codec. Each package keeps its own model mapping, duplicate-key validation, header interpretation, and fuzzy policy, and raises its own public diagnostic exception through an injected error factory (no internal exception type crosses the boundary). The grammar is stricter and uniform in two documented ways: BOM tolerance applies to both consumers, and a header entry without `msgstr` is a grammar violation in both.
- PO, ResX, and diagnostic string literals that repeated three or more times are now named constants (`MSGCTXT`/`MSGID`/`MSGID_PLURAL`/`MSGSTR`, `VALUE_ELEMENT`, `LOOKUP_COUNT_UNIT`), closing 14 duplicate-literal findings.
- The architecture identity tests exclude the coverage collector's injected instrumentation namespace (`Coverlet.*`), so the full suite stays green while `XPlat Code Coverage` instruments the assemblies; `tests/Jeninnet.Localization.Tests/.runsettings` is committed for the coverage and Sonar paths.
- `src/Jeninnet.Localization.Core/GlobalUsings.cs` was restored to its canonical casing (the working copy had drifted to lower case, which broke SCM blame for that file).
- The local Sonar preview tool (`scripts/sonar/preview.ps1`) now waits for the exact compute-engine task reported by the scanner before reading issues and the quality gate (a previous analysis's status is never reported as current), targets a local SonarQube server with `-Local` (token from `SONAR_TOKEN_LOCAL`, server `http://localhost:9000`, no organization or branch parameters), accepts `-ServerUrl`/`-ProjectKey` overrides, resolves `SONAR_JAVA_PATH`, tolerates a tools directory missing from `PATH`, and maps the scanner's `MissingObjectException` blame failure to an actionable hint.
- Public constants renamed to `ALL_UPPER_SNAKE` per the committed naming rules (IDE1006); private fields use the `_camelCase` prefix and async methods carry the `Async` suffix. The public-API baselines were regenerated accordingly (the unreleased surface contains canonical names only), and the repository contains zero `[Obsolete]` members — enforced by an architecture test.
- Maintainer-internal process documents moved out of the repository into a separate local workspace; project documentation and the solution file no longer reference them, and the documentation gate rejects links to git-ignored paths.
- Documentation publishing now runs automatically from the `Documentation` workflow on `main` whenever documentation, source, or integration projects change; the separate manual deployment workflow was removed.
- Reference application layout flattened under `samples/`: the intermediate `Reference/`, `Hosts/`, and per-category folders were removed so every project sits directly in `samples/` (for example `samples/Jeninnet.Localization.Reference.Hosts.Desktop.Tests/`), keeping generated build paths well under the Windows MAX_PATH limit.
- Test assertions migrated to the external `Jeninnet.Assertions` 1.0.0 NuGet package (namespace `Jeninnet.Assertions`), replacing the temporary `Jeninnet.Testing.Assertions` 0.1.0-alpha package now that the library lives in its own standalone repository.
- Provider options are captured as immutable construction snapshots, so post-registration mutation of caller-owned options no longer changes provider behavior.
- JSON and XML provider initialization is synchronized and retry-safe.
- Dependency closure reconciled for .NET 10 consumers: the MVC validation integration uses the `Microsoft.AspNetCore.App` shared framework, and the unused `Newtonsoft.Json` reference was removed.

### Fixed

- The Blazor Server and Blazor Hybrid reference hosts no longer fail the build on Sonar `S8970` findings emitted inside Razor source-generator output (`#nullable disable` context); the rule stays active for handwritten code.
- Localizers no longer serve a permanently empty resource set after a temporary store miss.
- Azure translation caching is bounded, and a refresh no longer allows stale in-flight completions to repopulate current state.
